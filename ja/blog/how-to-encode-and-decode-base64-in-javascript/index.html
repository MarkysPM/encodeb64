JavaScriptでBase64をエンコード・デコードする方法

2026年11月読了時間約8分

JavaScriptにはBase64を扱う方法がいくつかあり、適切なものはコードの実行環境によって決まります。ブラウザにはbtoa()とatob()があり、Node.jsにはBufferがあります。どちらの環境でも、Unicodeを正しく扱うためにTextEncoderとTextDecoderを使えます。このガイドでは、それぞれの方法と、多くの開発者がはまる落とし穴を取り上げます。

btoa()とatob()による基本的なエンコード

btoa()（binary to ASCII）は文字列をBase64にエンコードし、atob()（ASCII to binary）はそれをデコードします。すべての最新ブラウザと、Node.js 16以降で利用できます。

const encoded = btoa('Hello, World!'); console.log(encoded); // "SGVsbG8sIFdvcmxkIQ==" const decoded = atob(encoded); console.log(decoded); // "Hello, World!"

これは単純なASCIIテキストなら動作します。問題は、それ以外の文字から始まります。

Unicodeの問題

btoa()は各文字を1バイトとして扱うため、コードポイントが0〜255の文字しか受け付けません。絵文字や、ラテン文字以外のほとんどのテキストを渡すとエラーになります。

btoa('café ☕'); // Uncaught InvalidCharacterError: String contains an invalid character

解決策は、まず文字列をUTF-8のバイト列に変換し、そのバイト列をエンコードすることです。

Unicodeテキストを正しくエンコードする

TextEncoderは文字列をUTF-8バイトのUint8Arrayに変換します。そのバイトをバイナリ文字列にしてbtoa()に渡します。

function encodeBase64(text) { const bytes = new TextEncoder().encode(text); let binary = ''; bytes.forEach((b) => (binary += String.fromCharCode(b))); return btoa(binary); } function decodeBase64(base64) { const binary = atob(base64); const bytes = Uint8Array.from(binary, (c) => c.charCodeAt(0)); return new TextDecoder().decode(bytes); } encodeBase64('café ☕'); // "Y2Fmw6kg4piV" decodeBase64('Y2Fmw6kg4piV'); // "café ☕"

入力に基本的なASCII以外の文字が含まれる可能性があるときは、必ずこの2つの関数を使ってください。名前、コメント、メッセージなど、ユーザーが入力するテキストにも使えます。

Node.jsではBufferでBase64を扱う

Node.jsでは、Bufferが最も簡単で高速な方法で、UTF-8も自動で処理してくれます。

const encoded = Buffer.from('café ☕', 'utf8').toString('base64'); console.log(encoded); // "Y2Fmw6kg4piV" const decoded = Buffer.from(encoded, 'base64').toString('utf8'); console.log(decoded); // "café ☕"

Node.jsにもbtoa()とatob()はありますが、サーバー側のコードではBufferが推奨されます。バイナリデータを直接扱え、文字列を経由する必要がないためです。

JavaScriptでのBase64URL

Base64URLは+を-に、/を_に置き換え、通常は=のパディングを取り除きます。Node.js 15.7以降では、直接指定できます。

Buffer.from('subjects?_d').toString('base64url'); // "c3ViamVjdHM_X2Q"

ブラウザでは、標準の出力を自分で変換します。

function toBase64Url(base64) { return base64.replace(/\+/g, '-').replace(/\//g, '_').replace(/=+$/, ''); } function fromBase64Url(base64url) { let base64 = base64url.replace(/-/g, '+').replace(/_/g, '/'); while (base64.length % 4) base64 += '='; return base64; }

atob()を呼ぶ前にパディングを復元するのを忘れないでください。長さが4の倍数でない入力を拒否するデコーダーがあるためです。

ファイルや画像をエンコードする

ブラウザでは、FileReader.readAsDataURL()がファイルを読み込み、Base64データを含む完全なdata URIを返します。

const input = document.querySelector('input[type="file"]'); input.addEventListener('change', () => { const reader = new FileReader(); reader.onload = () => { console.log(reader.result); // "data:image/png;base64,iVBORw0KGgo..." }; reader.readAsDataURL(input.files[0]); });

Base64の部分だけが必要な場合は、最初のカンマまでを取り除きます：reader.result.split(',')[1]。コードを書かずに手早く変換したいときは、画像からBase64への変換ツールを使ってください。

Node.jsでは、ファイルをバッファに読み込んでエンコードします。

import { readFileSync } from 'node:fs'; const base64 = readFileSync('photo.png').toString('base64');

よくあるエラーと対処法

InvalidCharacterError: String contains an invalid character
原因：btoa()にコードポイントが255を超える文字を含む文字列を渡した。対処：上記のように、まずUTF-8のバイト列にエンコードする。

atob()の呼び出し時のInvalidCharacterError
原因：入力にBase64のアルファベット以外の文字が含まれている。Base64URL文字列の-や_、空白や改行であることが多い。対処：Base64URLを標準のBase64に戻し、前後の空白を取り除く。

デコード結果にÃ©のような奇妙な文字が出る
原因：バイトはUTF-8なのに、atob()が既定で返すLatin-1として解釈された。対処：TextDecoderでバイトをデコードする。

大きなファイルで出力が壊れる
原因：String.fromCharCode(...bytes)で巨大な文字列を一度に作ると、エンジンの引数の上限を超えることがある。対処：バイトをループで処理するか、チャンクに分けて処理するか、FileReaderやBufferを使う。

新しいAPIについての補足

新しいJavaScriptエンジンでは、Base64との相互変換を行う組み込みメソッドがUint8Arrayに追加されつつあります。ブラウザ間の対応状況はまだ一様ではないため、本番環境で頼る前に最新の互換性表を確認してください。このガイドの関数は、現時点でどこでも動作します。
