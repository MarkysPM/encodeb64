Erros comuns de Base64 e como corrigi-los

Novembro de 20268 min de leitura

Base64 é simples, mas produz algumas das mensagens de erro mais confusas da programação: Incorrect padding, Invalid character, The input is not a valid Base-64 string. As mensagens mudam conforme a linguagem, mas as causas quase sempre são as mesmas poucas. Este guia as lista na ordem em que você deve verificá-las, com o sintoma, a causa e a correção de cada uma.

Primeiro passo: olhe a string

Antes de mudar o código, olhe a string real que você está tentando decodificar. Quatro verificações rápidas respondem à maioria das dúvidas:

  • Ela contém - ou _? Então é Base64URL, não Base64 padrão.
  • Ela contém + ou /? Então é Base64 padrão.
  • Ela termina em = ou ==? Se deveria e não termina, o preenchimento foi removido.
  • Ela começa com data:? Então é uma URI de dados e só a parte depois da vírgula é Base64.

1. Preenchimento ausente ou incorreto

Sintomas: Incorrect padding (Python), illegal base64 data at input byte N (Go), Invalid length for a Base-64 char array (.NET).

Causa: o tamanho da string não é múltiplo de quatro porque os = finais foram removidos, algo normal em JWTs, URLs e algumas APIs.

Correção: adicione o preenchimento que falta antes de decodificar. O número de = necessários é (4 - tamanho % 4) % 4:

def fix_padding(s): return s + '=' * (-len(s) % 4)

Uma verificação útil: uma string Base64 válida, com ou sem preenchimento, nunca pode ter tamanho 1 módulo 4. Se tamanho % 4 == 1, os dados estão truncados ou corrompidos e nenhum preenchimento resolverá.

2. Confusão entre o alfabeto padrão e o seguro para URL

Sintomas: Invalid character ou Illegal base64 character 2d (onde 2d é o código hexadecimal de um hífen), ou uma saída que decodifica sem erro, mas está errada.

Causa: uma string Base64URL (com - e _) foi entregue a um decodificador padrão, ou o contrário.

Correção: use o decodificador que corresponde aos dados, ou traduza os caracteres antes: troque - por + e _ por / para ir do formato seguro para URL ao padrão. Veja Base64URL vs Base64 para saber quando cada um é usado.

3. Sinais de mais transformados em espaços

Sintomas: os dados decodificados estão corrompidos, ou o decodificador reclama de um espaço, mas apenas com valores que vieram por uma URL ou formulário HTML.

Causa: em query strings de URL e em corpos de formulário, um + significa espaço. Um valor Base64 padrão colocado em uma URL sem codificação percentual chega com os + trocados por espaços.

Correção: nunca coloque Base64 padrão em uma URL sem escapar. Codifique com porcentagem (+ vira %2B, / vira %2F, = vira %3D) ou, melhor, use Base64URL. Como socorro no lado receptor, troque os espaços por + antes de decodificar.

4. Espaços em branco e quebras de linha

Sintomas: Illegal base64 character 20 (espaço) ou 0a (quebra de linha) no Java, FormatException no .NET, ou uma falha apenas com valores longos.

Causa: o valor foi quebrado em 76 caracteres, copiado de um e-mail ou de um arquivo PEM, ou tem uma quebra de linha no final.

Correção: remova os espaços em branco antes de decodificar (re.sub(r'\s+', '', s) em Python, s.replace(/\s+/g, '') em JavaScript), ou use um decodificador que os tolere, como o decodificador MIME do Java. Fique de olho também na quebra de linha final que o echo adiciona ao codificar na linha de comando.

5. Incluir o prefixo da URI de dados

Sintomas: um erro que menciona dois-pontos ou ponto e vírgula, ou uma saída ilegível ao decodificar algo copiado de um atributo <img src>.

Causa: o decodificador recebeu data:image/png;base64,iVBORw0... em vez de apenas iVBORw0....

Correção: divida pela primeira vírgula e decodifique só a segunda parte: s.split(',', 1)[1]. Se você só precisa da imagem, também pode usar a string Base64 diretamente como src depois de adicionar o prefixo. Nosso conversor de imagem para Base64 produz as duas formas.

6. O texto decodifica como lixo ou caracteres estranhos

Sintomas: a decodificação funciona, mas o texto contém Ã©, â€™ ou pontos de interrogação.

Causa: incompatibilidade de codificação de caracteres. Os bytes são UTF-8, mas foram interpretados como Latin-1 ou Windows-1252. O inverso também acontece: texto codificado em UTF-16 (o padrão de Encoding.Unicode no .NET e de -EncodedCommand no PowerShell) decodificado como UTF-8 mostra caracteres nulos entre as letras.

Correção: faça os dois lados concordarem sobre a codificação do texto e use UTF-8, a menos que tenha motivo para não usar. Se os dados decodificados não forem texto (uma imagem, um PDF, um bloco criptografado), não os converta em string; mantenha-os como bytes.

7. Codificação dupla

Sintomas: depois de decodificar, você obtém outra string com cara de Base64, geralmente começando com ey ou SG.

Causa: os dados foram codificados duas vezes, normalmente porque uma camada do seu código e uma biblioteca aplicaram Base64.

Correção: decodifique de novo e depois remova a etapa de codificação extra na origem. Um teste rápido: o Base64 real de um texto comum costuma começar com uma letra, e um resultado que por si só é Base64 válido é um forte sinal de codificação dupla.

8. Dados truncados ou corrompidos

Sintomas: um erro em uma posição específica de byte, tamanho 1 módulo 4 ou um arquivo que abre só parcialmente.

Causa: a string foi cortada por um limite de colunas, um limite de linha de log, um limite de tamanho de URL ou um erro de copiar e colar.

Correção: compare o tamanho da string na origem e no destino e verifique os limites de cada sistema no meio do caminho. O Base64 não tem detecção de erros, então, se precisar de integridade, envie uma soma de verificação separadamente.

9. O tipo de entrada errado

Sintomas: decodificar um hash, um UUID ou uma string hex e receber bytes ilegíveis.

Causa: nem toda string com cara de Base64 é Base64. Strings hex e alguns identificadores usam apenas caracteres que também existem no alfabeto Base64, então um decodificador os decodificará de bom grado em bytes sem sentido.

Correção: confirme o formato com quem produziu os dados. Hex usa apenas 0-9 e a-f e tem tamanho par.

Uma lista de verificação para depuração

  1. Imprima a string exata e seu tamanho.
  2. Identifique o alfabeto (+/ ou -_).
  3. Remova espaços em branco e qualquer prefixo data:.
  4. Restaure o preenchimento se o tamanho não for múltiplo de quatro.
  5. Decodifique para bytes e só então decida se é texto.
  6. Se ainda falhar, cole a string em decodeb64.com para confirmar se o problema está nos dados ou no seu código.
