How to Encode and Decode Base64 in JavaScript

November 20268 min read

JavaScript gives you several ways to work with Base64, and the right one depends on where your code runs. Browsers provide btoa() and atob(). Node.js provides Buffer. Both environments can also use TextEncoder and TextDecoder to handle Unicode correctly. This guide covers each approach and the pitfalls that catch most developers.

Basic Encoding With btoa() and atob()

btoa() (binary to ASCII) encodes a string to Base64, and atob() (ASCII to binary) decodes it. They are available in all modern browsers and in Node.js 16 and later.

const encoded = btoa('Hello, World!'); console.log(encoded); // "SGVsbG8sIFdvcmxkIQ==" const decoded = atob(encoded); console.log(decoded); // "Hello, World!"

This works for plain ASCII text. The problem starts with anything else.

The Unicode Problem

btoa() treats each character as one byte, so it only accepts characters with code points from 0 to 255. Passing an emoji or most non-Latin text throws an error:

btoa('café ☕'); // Uncaught InvalidCharacterError: String contains an invalid character

The fix is to convert the string to UTF-8 bytes first, then encode those bytes.

Encoding Unicode Text Correctly

TextEncoder converts a string to a Uint8Array of UTF-8 bytes. Turn those bytes into a binary string and pass it to btoa():

function encodeBase64(text) { const bytes = new TextEncoder().encode(text); let binary = ''; bytes.forEach((b) => (binary += String.fromCharCode(b))); return btoa(binary); } function decodeBase64(base64) { const binary = atob(base64); const bytes = Uint8Array.from(binary, (c) => c.charCodeAt(0)); return new TextDecoder().decode(bytes); } encodeBase64('café ☕'); // "Y2Fmw6kg4piV" decodeBase64('Y2Fmw6kg4piV'); // "café ☕"

Use these two helpers whenever the input may contain anything beyond basic ASCII. They also work for any user-provided text, such as names, comments or messages.

Base64 in Node.js With Buffer

In Node.js the simplest and fastest option is Buffer, which handles UTF-8 for you:

const encoded = Buffer.from('café ☕', 'utf8').toString('base64'); console.log(encoded); // "Y2Fmw6kg4piV" const decoded = Buffer.from(encoded, 'base64').toString('utf8'); console.log(decoded); // "café ☕"

btoa() and atob() also exist in Node.js, but Buffer is preferred for server code because it works with binary data directly and does not require the string round trip.

Base64URL in JavaScript

Base64URL replaces + with -, / with _ and usually removes the = padding. In Node.js 15.7 and later you can ask for it directly:

Buffer.from('subjects?_d').toString('base64url'); // "c3ViamVjdHM_X2Q"

In the browser, convert the standard output yourself:

function toBase64Url(base64) { return base64.replace(/\+/g, '-').replace(/\//g, '_').replace(/=+$/, ''); } function fromBase64Url(base64url) { let base64 = base64url.replace(/-/g, '+').replace(/_/g, '/'); while (base64.length % 4) base64 += '='; return base64; }

Remember to restore the padding before calling atob(), because some decoders reject input whose length is not a multiple of four.

Encoding a File or Image

In the browser, FileReader.readAsDataURL() reads a file and returns a complete data URI that already contains the Base64 data:

const input = document.querySelector('input[type="file"]'); input.addEventListener('change', () => { const reader = new FileReader(); reader.onload = () => { console.log(reader.result); // "data:image/png;base64,iVBORw0KGgo..." }; reader.readAsDataURL(input.files[0]); });

To keep only the Base64 part, strip everything up to the first comma: reader.result.split(',')[1]. For a quick conversion without code, use the Image to Base64 converter.

In Node.js, read the file into a buffer and encode it:

import { readFileSync } from 'node:fs'; const base64 = readFileSync('photo.png').toString('base64');

Common Errors and Fixes

InvalidCharacterError: String contains an invalid character
Cause: you passed a string with characters above code point 255 to btoa(). Fix: encode to UTF-8 bytes first, as shown above.

InvalidCharacterError when calling atob()
Cause: the input contains characters that are not in the Base64 alphabet, often - and _ from a Base64URL string, or whitespace and line breaks. Fix: convert Base64URL back to standard Base64 and trim the input.

Decoded text shows strange characters such as Ã©
Cause: the bytes were UTF-8 but were decoded as Latin-1, which is what atob() returns by default. Fix: decode the bytes with TextDecoder.

Corrupted output for large files
Cause: building one huge string with String.fromCharCode(...bytes) can exceed the engine's argument limit. Fix: loop over the bytes, process them in chunks, or use FileReader or Buffer.

A Note on Newer APIs

Newer JavaScript engines are adding built-in methods on Uint8Array for converting to and from Base64. Support is still uneven across browsers, so check current compatibility tables before relying on them in production. The helpers in this guide work everywhere today.
