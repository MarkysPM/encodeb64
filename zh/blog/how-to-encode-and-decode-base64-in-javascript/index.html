如何在 JavaScript 中进行 Base64 编码和解码

2026年11月阅读时间约 8 分钟

JavaScript 提供了多种使用 Base64 的方式，选择哪一种取决于代码运行的环境。浏览器提供 btoa() 和 atob()，Node.js 提供 Buffer。这两种环境也都可以使用 TextEncoder 和 TextDecoder 来正确处理 Unicode。本文介绍每一种方法，以及大多数开发者容易踩的坑。

使用 btoa() 和 atob() 进行基本编码

btoa()（binary to ASCII）把字符串编码为 Base64，atob()（ASCII to binary）则把它解码。所有现代浏览器以及 Node.js 16 及更高版本都支持它们。

const encoded = btoa('Hello, World!'); console.log(encoded); // "SGVsbG8sIFdvcmxkIQ==" const decoded = atob(encoded); console.log(decoded); // "Hello, World!"

这对普通 ASCII 文本有效。一旦遇到其他内容，问题就出现了。

Unicode 问题

btoa() 把每个字符当作一个字节，因此只接受码点在 0 到 255 之间的字符。传入表情符号或大多数非拉丁文字都会抛出错误：

btoa('café ☕'); // Uncaught InvalidCharacterError: String contains an invalid character

解决办法是先把字符串转换为 UTF-8 字节，再对这些字节进行编码。

正确编码 Unicode 文本

TextEncoder 会把字符串转换为由 UTF-8 字节组成的 Uint8Array。把这些字节转成二进制字符串，再传给 btoa()：

function encodeBase64(text) { const bytes = new TextEncoder().encode(text); let binary = ''; bytes.forEach((b) => (binary += String.fromCharCode(b))); return btoa(binary); } function decodeBase64(base64) { const binary = atob(base64); const bytes = Uint8Array.from(binary, (c) => c.charCodeAt(0)); return new TextDecoder().decode(bytes); } encodeBase64('café ☕'); // "Y2Fmw6kg4piV" decodeBase64('Y2Fmw6kg4piV'); // "café ☕"

只要输入可能包含基本 ASCII 以外的内容，就应使用这两个函数。它们同样适用于用户输入的任何文本，例如姓名、评论或消息。

在 Node.js 中使用 Buffer 处理 Base64

在 Node.js 中，最简单也最快的选择是 Buffer，它会替你处理 UTF-8：

const encoded = Buffer.from('café ☕', 'utf8').toString('base64'); console.log(encoded); // "Y2Fmw6kg4piV" const decoded = Buffer.from(encoded, 'base64').toString('utf8'); console.log(decoded); // "café ☕"

Node.js 中也有 btoa() 和 atob()，但服务端代码更推荐使用 Buffer，因为它直接处理二进制数据，不需要经过字符串中转。

JavaScript 中的 Base64URL

Base64URL 把 + 换成 -，把 / 换成 _，并且通常去掉 = 填充。在 Node.js 15.7 及更高版本中，可以直接指定：

Buffer.from('subjects?_d').toString('base64url'); // "c3ViamVjdHM_X2Q"

在浏览器中，需要自己转换标准输出：

function toBase64Url(base64) { return base64.replace(/\+/g, '-').replace(/\//g, '_').replace(/=+$/, ''); } function fromBase64Url(base64url) { let base64 = base64url.replace(/-/g, '+').replace(/_/g, '/'); while (base64.length % 4) base64 += '='; return base64; }

调用 atob() 之前别忘了恢复填充，因为有些解码器会拒绝长度不是 4 的倍数的输入。

编码文件或图片

在浏览器中，FileReader.readAsDataURL() 会读取文件并返回完整的 data URI，其中已经包含 Base64 数据：

const input = document.querySelector('input[type="file"]'); input.addEventListener('change', () => { const reader = new FileReader(); reader.onload = () => { console.log(reader.result); // "data:image/png;base64,iVBORw0KGgo..." }; reader.readAsDataURL(input.files[0]); });

如果只想保留 Base64 部分，请去掉第一个逗号之前的所有内容：reader.result.split(',')[1]。如需无需代码的快速转换，请使用图片转 Base64 工具。

在 Node.js 中，把文件读入缓冲区后再编码：

import { readFileSync } from 'node:fs'; const base64 = readFileSync('photo.png').toString('base64');

常见错误与解决办法

InvalidCharacterError: String contains an invalid character
原因：传给 btoa() 的字符串包含码点大于 255 的字符。解决：如上所示，先编码为 UTF-8 字节。

调用 atob() 时出现 InvalidCharacterError
原因：输入中含有不属于 Base64 字母表的字符，常见的是 Base64URL 字符串里的 - 和 _，或是空白和换行。解决：把 Base64URL 转回标准 Base64，并去掉首尾空白。

解码后的文本出现 Ã© 之类的怪字符
原因：字节本是 UTF-8，却被当作 Latin-1 解读，而 atob() 默认返回的就是后者。解决：用 TextDecoder 解码这些字节。

大文件的输出损坏
原因：用 String.fromCharCode(...bytes) 构造一个巨大的字符串，可能超出引擎的参数数量上限。解决：循环处理字节、分块处理，或使用 FileReader 或 Buffer。

关于较新 API 的说明

较新的 JavaScript 引擎正在为 Uint8Array 添加与 Base64 互相转换的内置方法。目前各浏览器的支持情况还不一致，因此在生产环境中依赖它们之前，请先查阅最新的兼容性表。本文中的函数如今在所有环境下都能使用。
