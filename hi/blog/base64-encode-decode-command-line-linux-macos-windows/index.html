कमांड लाइन पर Base64: Linux, macOS और Windows

नवंबर 20266 मिनट पढ़ने का समय

Base64 के साथ काम करने के लिए आपको किसी वेबसाइट या स्क्रिप्ट की ज़रूरत नहीं है। हर प्रमुख ऑपरेटिंग सिस्टम में ऐसे टूल आते हैं जो टर्मिनल से इसे एन्कोड और डिकोड कर सकते हैं। टोकन जाँचने, कॉन्फ़िगरेशन फ़ाइलों के लिए सीक्रेट बनाने या छोटी फ़ाइलें बदलने में यह काम आता है। यह गाइड Linux, macOS और Windows को कवर करती है और उन अंतरों की ओर इशारा करती है जिनसे भ्रमित करने वाले नतीजे आते हैं।

Linux: base64 कमांड

GNU base64 कमांड coreutils का हिस्सा है और लगभग हर Linux वितरण में इंस्टॉल होता है।

एक स्ट्रिंग को एन्कोड करें:

echo -n 'Hello, World!' | base64 # SGVsbG8sIFdvcmxkIQ==

उसे डिकोड करें:

echo 'SGVsbG8sIFdvcmxkIQ==' | base64 --decode # Hello, World!

फ़ाइलें एन्कोड और डिकोड करें:

base64 photo.png > photo.b64 base64 --decode photo.b64 > photo-copy.png

अंत की नई पंक्ति का जाल

यह सबसे आम गलती है। सादा echo अपने आउटपुट में एक नई पंक्ति का वर्ण जोड़ देता है, और वह नई पंक्ति एन्कोड होने वाले डेटा का हिस्सा बन जाती है:

echo 'Hello' | base64 # SGVsbG8K (encodes "Hello\n") echo -n 'Hello' | base64 # SGVsbG8= (encodes "Hello")

अगर कोई पासवर्ड, API कुंजी या टोकन टर्मिनल में एन्कोड करने के बाद “काम नहीं करता”, तो एक अतिरिक्त नई पंक्ति ही संभावित दोषी है। हमेशा echo -n इस्तेमाल करें, या printf '%s' 'Hello' का उपयोग करें, जो हर शेल में एक जैसा व्यवहार करता है।

लाइन रैपिंग

GNU base64 76 वर्णों के बाद आउटपुट को लपेट देता है। फ़ाइलों के लिए यह ठीक है, लेकिन JSON, एनवायरनमेंट वेरिएबल या HTTP हेडर में पेस्ट करने के लिए नहीं। -w 0 से रैपिंग बंद करें:

base64 -w 0 photo.png

macOS

macOS में base64 का BSD संस्करण आता है, जो थोड़े अलग विकल्प स्वीकार करता है। पाइप के साथ बुनियादी एन्कोडिंग उसी तरह काम करती है:

echo -n 'Hello, World!' | base64 echo 'SGVsbG8sIFdvcmxkIQ==' | base64 --decode

इनपुट फ़ाइल के लिए -i और आउटपुट फ़ाइल के लिए -o इस्तेमाल करें:

base64 -i photo.png -o photo.b64

GNU का विकल्प -w 0 macOS पर उपलब्ध नहीं है, और पुराने macOS संस्करण -d या --decode की जगह -D इस्तेमाल करते थे। अगर कोई स्क्रिप्ट दोनों सिस्टम पर चलनी है, तो प्लेटफ़ॉर्म जाँचें या नीचे बताया गया openssl इस्तेमाल करें।

openssl: पोर्टेबल विकल्प

OpenSSL Linux, macOS और Windows (Git for Windows या WSL के ज़रिए) पर उपलब्ध है और एक जैसा व्यवहार करता है:

echo -n 'Hello, World!' | openssl base64 echo 'SGVsbG8sIFdvcmxkIQ==' | openssl base64 -d openssl base64 -in photo.png -out photo.b64

आउटपुट को लपेटने के बजाय एक ही पंक्ति में रखने के लिए -A जोड़ें।

Windows PowerShell

PowerShell सीधे .NET की Convert क्लास को कॉल कर सकता है। टेक्स्ट एन्कोड करें:

[Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes('Hello, World!')) # SGVsbG8sIFdvcmxkIQ==

टेक्स्ट डिकोड करें:

[Text.Encoding]::UTF8.GetString([Convert]::FromBase64String('SGVsbG8sIFdvcmxkIQ==')) # Hello, World!

किसी फ़ाइल को Base64 स्ट्रिंग में एन्कोड करें:

[Convert]::ToBase64String([IO.File]::ReadAllBytes('photo.png'))

किसी Base64 स्ट्रिंग को डिकोड करके फ़ाइल में लिखें:

[IO.File]::WriteAllBytes('photo-copy.png', [Convert]::FromBase64String($base64))

ध्यान दें कि आप टेक्स्ट एन्कोडिंग स्पष्ट रूप से चुनते हैं (UTF8)। अगर आप इसकी जगह Unicode इस्तेमाल करते हैं, तो PowerShell UTF-16 अपनाता है और नतीजा Linux और macOS से अलग होगा।

Windows certutil

पुराना टूल certutil किसी भी Windows सिस्टम पर कमांड प्रॉम्प्ट से चलता है:

certutil -encode photo.png photo.b64 certutil -decode photo.b64 photo-copy.png

ध्यान रहे कि certutil -encode आउटपुट को -----BEGIN CERTIFICATE----- हेडर और फ़ुटर पंक्तियों में लपेट देता है। अगर आपको केवल Base64 टेक्स्ट चाहिए तो उन पंक्तियों को हटा दें।

टर्मिनल से Base64URL डिकोड करना

JWT और कई आधुनिक API URL-सुरक्षित वर्णमाला का उपयोग करते हैं और पैडिंग छोड़ देते हैं, इसलिए सादा base64 --decode विफल हो सकता है। पहले वर्णों को बदलें और पैडिंग वापस जोड़ें:

value='eyJhbGciOiJIUzI1NiJ9' len=$(( ${#value} % 4 )) [ $len -eq 2 ] && value="$value==" [ $len -eq 3 ] && value="$value=" echo "$value" | tr '_-' '/+' | base64 --decode # {"alg":"HS256"}

ये टोकन अलग क्यों दिखते हैं, यह समझने के लिए JWT टोकन Base64URL एन्कोडिंग का उपयोग कैसे करते हैं पढ़ें।

त्वरित तुलना

  • Linux: base64, एक पंक्ति के लिए -w 0 के साथ।
  • macOS: base64 के साथ -i और -o; -w विकल्प नहीं है।
  • क्रॉस-प्लेटफ़ॉर्म: openssl base64।
  • Windows: PowerShell का [Convert] या certutil।
