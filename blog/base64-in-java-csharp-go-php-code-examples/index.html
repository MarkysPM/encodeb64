Base64 in Java, C#, Go and PHP: Code Examples

November 20267 min read

Every mainstream language ships with Base64 support, but the names, defaults and failure behavior differ in ways that cause real bugs, especially around URL-safe output, padding and invalid input. This guide gives you compact, copy-ready examples for Java, C#, Go and PHP, and points out the differences worth knowing. For JavaScript and Python, see our guides to JavaScript and Python.

The Test String Used in These Examples

All the examples encode the text Hello, World!, which should produce the same result in every language:

SGVsbG8sIFdvcmxkIQ==

If your output differs, check the character encoding. Always convert text to UTF-8 bytes before encoding; otherwise results differ between platforms for non-ASCII text.

Java

Since Java 8, the java.util.Base64 class has been the standard tool. Avoid the old sun.misc.BASE64Encoder and third-party helpers in new code.

import java.util.Base64; import java.nio.charset.StandardCharsets; String encoded = Base64.getEncoder() .encodeToString("Hello, World!".getBytes(StandardCharsets.UTF_8)); // SGVsbG8sIFdvcmxkIQ== byte[] decoded = Base64.getDecoder().decode(encoded); String text = new String(decoded, StandardCharsets.UTF_8);

Java provides three encoder and decoder families:

  • getEncoder() and getDecoder() for standard Base64.
  • getUrlEncoder() and getUrlDecoder() for the URL-safe alphabet.
  • getMimeEncoder() and getMimeDecoder() for MIME, which wraps lines at 76 characters and ignores line breaks when decoding.

To drop the = padding, as JWT does, chain withoutPadding():

String token = Base64.getUrlEncoder().withoutPadding() .encodeToString("subjects?_d".getBytes(StandardCharsets.UTF_8)); // c3ViamVjdHM_X2Q

Invalid input throws IllegalArgumentException. For example, decoding a string that contains a space with the standard decoder fails with a message such as Illegal base64 character 20 (the hexadecimal code of the space). If your input may contain line breaks, use getMimeDecoder() instead.

C# and .NET

The Convert class handles standard Base64:

using System; using System.Text; string encoded = Convert.ToBase64String(Encoding.UTF8.GetBytes("Hello, World!")); // SGVsbG8sIFdvcmxkIQ== byte[] decoded = Convert.FromBase64String(encoded); string text = Encoding.UTF8.GetString(decoded);

Convert.FromBase64String throws a FormatException on invalid input. To avoid exceptions in hot paths, use the non-throwing pattern with Convert.TryFromBase64String and a pre-allocated buffer.

The classic Convert class has no URL-safe mode. Recent .NET versions add a dedicated Base64Url class in System.Buffers.Text, and ASP.NET Core provides WebEncoders.Base64UrlEncode. If neither is available to you, convert manually:

string url = Convert.ToBase64String(bytes) .TrimEnd('=') .Replace('+', '-') .Replace('/', '_');

One more trap: Encoding.Unicode in .NET is UTF-16, not UTF-8. Using it produces different Base64 from most other languages.

Go

The encoding/base64 package exposes ready-made encodings as variables, so the choice of alphabet and padding is explicit:

import "encoding/base64" encoded := base64.StdEncoding.EncodeToString([]byte("Hello, World!")) // SGVsbG8sIFdvcmxkIQ== decoded, err := base64.StdEncoding.DecodeString(encoded) if err != nil { // invalid input } text := string(decoded)

The four standard encodings are:

  • StdEncoding: standard alphabet, with padding.
  • URLEncoding: URL-safe alphabet, with padding.
  • RawStdEncoding: standard alphabet, without padding.
  • RawURLEncoding: URL-safe alphabet, without padding. This is the one JWT libraries use.

Go is strict. Decoding with StdEncoding a string whose padding was removed fails with an error such as illegal base64 data at input byte N, so you must pick the encoding that matches your data exactly.

PHP

PHP has two built-in functions:

$encoded = base64_encode('Hello, World!'); // SGVsbG8sIFdvcmxkIQ== $decoded = base64_decode($encoded, true); if ($decoded === false) { // invalid input }

Always pass true as the second argument to base64_decode. Without it, PHP silently ignores characters outside the alphabet, so malformed input may produce garbage instead of an error. In strict mode the function returns false on invalid input.

PHP has no built-in URL-safe functions, so use strtr:

function base64url_encode(string $data): string { return rtrim(strtr(base64_encode($data), '+/', '-_'), '='); } function base64url_decode(string $data): string|false { return base64_decode(strtr($data, '-_', '+/')); }

Behavior Differences at a Glance

  • Padding when decoding: Java’s URL decoder accepts missing padding, Go requires you to choose a Raw encoding, and .NET’s FromBase64String expects correct padding.
  • Whitespace: Java’s MIME decoder ignores line breaks; the standard decoders of Java, Go and .NET reject spaces in most cases; PHP drops them in non-strict mode.
  • Errors: Java throws IllegalArgumentException, .NET throws FormatException, Go returns an error and PHP returns false in strict mode.

For help diagnosing the messages above, read Common Base64 Errors and How to Fix Them.
