Base64URL vs Base64: diferenças e quando usar cada um

Agosto de 20264 min de leitura

Se você já trabalhou com tokens JWT, OAuth 2.0 ou parâmetros de URL, provavelmente já encontrou o Base64URL — uma variante do Base64 padrão que parece quase idêntica, mas se comporta de forma diferente em determinados contextos. Entender essa diferença pode economizar horas depurando erros de codificação enigmáticos.

O que é o Base64 padrão?

O Base64 padrão, definido na RFC 4648 §4, codifica dados binários usando 64 caracteres: A–Z, a–z, 0–9, mais (+) e barra (/). A saída é preenchida com sinais de igual (=) para que o comprimento seja múltiplo de 4. Por exemplo, codificar "Man" resulta em "TWFu".

O problema surge ao tentar usar uma string Base64 padrão em uma URL. O caractere + é interpretado como espaço em query strings de URL, e / é um separador de caminho. Uma string Base64 como "abc+def/ghi=" colocada em uma URL será interpretada incorretamente por servidores web e navegadores.

O que é Base64URL?

O Base64URL, definido na RFC 4648 §5, resolve isso fazendo duas substituições:

  • + é substituído por - (hífen)
  • / é substituído por _ (sublinhado)
  • o padding = é omitido completamente

Todos esses caracteres são seguros em URLs e nomes de arquivo sem precisar de codificação percentual. O mesmo exemplo "Man" é codificado como "TWFu" em ambas as variantes (sem caracteres especiais neste caso), mas uma string como "i+Uo/A==" em Base64 padrão se torna "i-Uo_A" em Base64URL.

Os tokens JWT usam Base64URL

Os JSON Web Tokens (JWT) são o lugar mais comum onde os desenvolvedores encontram o Base64URL. Um JWT é composto por três partes separadas por pontos: header.payload.signature. Tanto o header quanto o payload são codificados em Base64URL — não em Base64 padrão. É por isso que strings JWT contêm hífens e sublinhados, mas nunca sinais de mais ou barras.

Se você colar um JWT em um decodificador Base64 padrão sem converter os caracteres antes, terá um erro de decodificação ou uma saída ilegível. Sempre use um decodificador compatível com Base64URL para JWTs.

Convertendo entre os dois

Para converter uma string Base64 padrão em Base64URL:

  1. Substitua todos os + por -
  2. Substitua todas as / por _
  3. Remova todos os caracteres de padding =

Para converter Base64URL de volta para Base64 padrão:

  1. Substitua todos os - por +
  2. Substitua todos os _ por /
  3. Adicione padding = até o comprimento da string ser múltiplo de 4

Quando usar cada um

Use Base64 padrão quando:

  • Codificar anexos de e-mail (MIME, RFC 2045)
  • Incorporar imagens como Data URIs em HTML e CSS
  • Armazenar dados binários em payloads JSON ou XML onde o valor é colocado entre aspas
  • Trabalhar com sistemas que exigem especificamente o Base64 padrão

Use Base64URL quando:

  • Gerar ou analisar tokens JWT
  • Criar tokens seguros para URL para desafios PKCE do OAuth 2.0
  • Codificar dados para parâmetros de query de URL ou segmentos de caminho
  • Criar nomes de arquivo a partir de dados binários (nomes de arquivo não podem conter / na maioria dos sistemas)
  • Trabalhar com APIs de criptografia web, que normalmente geram Base64URL

Codificando com a variante correta

Em encodeb64.com, você pode alternar entre Base64 padrão e Base64URL usando a caixa de seleção "URL-safe encoding (Base64URL)" nas opções avançadas. A ferramenta aplica automaticamente as substituições de caracteres e remove o padding quando essa opção está ativada. Para decodificar qualquer uma das variantes, use decodeb64.com.

A diferença entre Base64 e Base64URL é pequena, mas importante. Em caso de dúvida, verifique a especificação do sistema com o qual está integrando — JWT sempre significa Base64URL, enquanto MIME sempre significa Base64 padrão com quebras de linha. Usar a variante errada é uma das causas mais comuns de bugs de codificação em aplicações web.
