명령줄에서 Base64 사용하기: Linux, macOS, Windows

2026년 11월읽는 시간 약 6분

Base64를 다루는 데 웹사이트나 스크립트는 필요하지 않습니다. 주요 운영체제에는 모두 터미널에서 Base64를 인코딩하고 디코딩할 수 있는 도구가 포함되어 있습니다. 토큰을 확인하거나, 설정 파일에 넣을 시크릿을 만들거나, 작은 파일을 변환할 때 유용합니다. 이 가이드는 Linux, macOS, Windows를 다루며 혼란스러운 결과를 낳는 차이점을 짚어 줍니다.

Linux: base64 명령

GNU base64 명령은 coreutils의 일부이며 거의 모든 Linux 배포판에 설치되어 있습니다.

문자열 인코딩하기:

echo -n 'Hello, World!' | base64 # SGVsbG8sIFdvcmxkIQ==

디코딩하기:

echo 'SGVsbG8sIFdvcmxkIQ==' | base64 --decode # Hello, World!

파일 인코딩과 디코딩:

base64 photo.png > photo.b64 base64 --decode photo.b64 > photo-copy.png

끝 줄 바꿈의 함정

가장 흔한 실수입니다. 일반 echo는 출력 끝에 줄 바꿈 문자를 추가하고, 그 줄 바꿈이 인코딩되는 데이터의 일부가 됩니다.

echo 'Hello' | base64 # SGVsbG8K (encodes "Hello\n") echo -n 'Hello' | base64 # SGVsbG8= (encodes "Hello")

터미널에서 인코딩한 비밀번호, API 키, 토큰이 “동작하지 않는다”면 불필요한 줄 바꿈이 원인일 가능성이 큽니다. 항상 echo -n을 사용하거나, 모든 셸에서 똑같이 동작하는 printf '%s' 'Hello'를 사용하세요.

출력의 줄 바꿈 처리

GNU base64는 76자마다 출력을 줄 바꿈합니다. 파일에는 괜찮지만 JSON, 환경 변수, HTTP 헤더에 붙여 넣기에는 적합하지 않습니다. -w 0으로 줄 바꿈을 끌 수 있습니다.

base64 -w 0 photo.png

macOS

macOS에는 BSD 버전의 base64가 포함되어 있으며 지원하는 옵션이 조금 다릅니다. 파이프를 사용한 기본 인코딩은 같은 방식으로 동작합니다.

echo -n 'Hello, World!' | base64 echo 'SGVsbG8sIFdvcmxkIQ==' | base64 --decode

입력 파일에는 -i, 출력 파일에는 -o를 사용합니다.

base64 -i photo.png -o photo.b64

GNU의 -w 0 옵션은 macOS에 없고, 오래된 macOS 버전은 -d나 --decode 대신 -D를 사용했습니다. 스크립트가 두 시스템에서 모두 동작해야 한다면 플랫폼을 확인하거나 아래에서 설명하는 openssl을 사용하세요.

openssl: 이식성 좋은 선택

OpenSSL은 Linux, macOS, Windows(Git for Windows 또는 WSL 이용)에서 사용할 수 있고 일관되게 동작합니다.

echo -n 'Hello, World!' | openssl base64 echo 'SGVsbG8sIFdvcmxkIQ==' | openssl base64 -d openssl base64 -in photo.png -out photo.b64

-A를 추가하면 출력을 줄 바꿈하지 않고 한 줄로 유지합니다.

Windows PowerShell

PowerShell은 .NET의 Convert 클래스를 직접 호출할 수 있습니다. 텍스트 인코딩:

[Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes('Hello, World!')) # SGVsbG8sIFdvcmxkIQ==

텍스트 디코딩:

[Text.Encoding]::UTF8.GetString([Convert]::FromBase64String('SGVsbG8sIFdvcmxkIQ==')) # Hello, World!

파일을 Base64 문자열로 인코딩하기:

[Convert]::ToBase64String([IO.File]::ReadAllBytes('photo.png'))

Base64 문자열을 디코딩해 파일로 저장하기:

[IO.File]::WriteAllBytes('photo-copy.png', [Convert]::FromBase64String($base64))

텍스트 인코딩을 명시적으로 선택한다는 점(UTF8)에 주목하세요. Unicode를 쓰면 PowerShell이 UTF-16을 사용하므로 Linux, macOS와는 결과가 달라집니다.

Windows certutil

기존 도구인 certutil은 모든 Windows 시스템의 명령 프롬프트에서 동작합니다.

certutil -encode photo.png photo.b64 certutil -decode photo.b64 photo-copy.png

certutil -encode는 출력을 -----BEGIN CERTIFICATE----- 머리글과 바닥글 줄로 감싼다는 점에 유의하세요. Base64 텍스트만 필요하면 그 줄들을 제거하세요.

터미널에서 Base64URL 디코딩하기

JWT와 많은 최신 API는 URL 안전 알파벳을 쓰고 패딩을 생략하므로 단순한 base64 --decode는 실패할 수 있습니다. 먼저 문자를 변환하고 패딩을 복원하세요.

value='eyJhbGciOiJIUzI1NiJ9' len=$(( ${#value} % 4 )) [ $len -eq 2 ] && value="$value==" [ $len -eq 3 ] && value="$value=" echo "$value" | tr '_-' '/+' | base64 --decode # {"alg":"HS256"}

이 토큰들이 왜 다르게 생겼는지 알고 싶다면 JWT 토큰이 Base64URL 인코딩을 사용하는 방식을 읽어 보세요.

빠른 비교

  • Linux: base64, 한 줄로 만들려면 -w 0.
  • macOS: base64에 -i와 -o. -w 옵션은 없음.
  • 크로스 플랫폼: openssl base64.
  • Windows: PowerShell의 [Convert] 또는 certutil.

일회성으로 필요하다면 온라인 인코더와 decodeb64.com이 브라우저에서 같은 일을 해 줍니다. 프로그램 안에서 Base64를 사용하려면 JavaScript와 Python 가이드를 참고하세요.
