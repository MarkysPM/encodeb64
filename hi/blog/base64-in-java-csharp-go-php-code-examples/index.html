Java, C#, Go और PHP में Base64: कोड उदाहरण

नवंबर 20267 मिनट पढ़ने का समय

हर प्रमुख भाषा में Base64 का समर्थन मौजूद है, लेकिन नाम, डिफ़ॉल्ट मान और विफलता पर व्यवहार ऐसे तरीकों से अलग हैं जो असली बग पैदा करते हैं, खासकर URL-सुरक्षित आउटपुट, पैडिंग और अमान्य इनपुट के मामले में। यह गाइड Java, C#, Go और PHP के संक्षिप्त, कॉपी करने योग्य उदाहरण देती है और उन अंतरों की ओर इशारा करती है जिन्हें जानना ज़रूरी है। JavaScript और Python के लिए हमारी JavaScript और Python गाइड देखें।

इन उदाहरणों में उपयोग की गई टेस्ट स्ट्रिंग

सभी उदाहरण टेक्स्ट Hello, World! को एन्कोड करते हैं, जिसका नतीजा हर भाषा में एक जैसा होना चाहिए:

SGVsbG8sIFdvcmxkIQ==

अगर आपका आउटपुट अलग है, तो कैरेक्टर एन्कोडिंग जाँचें। एन्कोड करने से पहले टेक्स्ट को हमेशा UTF-8 बाइट्स में बदलें; वरना गैर-ASCII टेक्स्ट के लिए अलग-अलग प्लेटफ़ॉर्म पर नतीजे भिन्न होंगे।

Java

Java 8 से java.util.Base64 क्लास मानक उपकरण रही है। नए कोड में पुराने sun.misc.BASE64Encoder और थर्ड-पार्टी हेल्पर से बचें।

import java.util.Base64; import java.nio.charset.StandardCharsets; String encoded = Base64.getEncoder() .encodeToString("Hello, World!".getBytes(StandardCharsets.UTF_8)); // SGVsbG8sIFdvcmxkIQ== byte[] decoded = Base64.getDecoder().decode(encoded); String text = new String(decoded, StandardCharsets.UTF_8);

Java तीन एन्कोडर और डिकोडर परिवार देता है:

  • getEncoder() और getDecoder() मानक Base64 के लिए।
  • getUrlEncoder() और getUrlDecoder() URL-सुरक्षित अक्षर-समूह के लिए।
  • getMimeEncoder() और getMimeDecoder() MIME के लिए, जो 76 अक्षरों पर पंक्तियाँ तोड़ता है और डिकोड करते समय लाइन ब्रेक को अनदेखा करता है।

JWT की तरह = पैडिंग हटाने के लिए withoutPadding() जोड़ें:

String token = Base64.getUrlEncoder().withoutPadding() .encodeToString("subjects?_d".getBytes(StandardCharsets.UTF_8)); // c3ViamVjdHM_X2Q

अमान्य इनपुट IllegalArgumentException फेंकता है। उदाहरण के लिए, स्पेस वाली स्ट्रिंग को मानक डिकोडर से डिकोड करने पर Illegal base64 character 20 (स्पेस का हेक्साडेसिमल कोड) जैसे संदेश के साथ विफलता होती है। अगर आपके इनपुट में लाइन ब्रेक हो सकते हैं, तो इसके बजाय getMimeDecoder() का उपयोग करें।

C# और .NET

Convert क्लास मानक Base64 संभालती है:

using System; using System.Text; string encoded = Convert.ToBase64String(Encoding.UTF8.GetBytes("Hello, World!")); // SGVsbG8sIFdvcmxkIQ== byte[] decoded = Convert.FromBase64String(encoded); string text = Encoding.UTF8.GetString(decoded);

अमान्य इनपुट पर Convert.FromBase64String FormatException फेंकता है। प्रदर्शन-संवेदनशील जगहों पर अपवाद से बचने के लिए पहले से आवंटित बफ़र के साथ Convert.TryFromBase64String वाला बिना-अपवाद पैटर्न अपनाएँ।

क्लासिक Convert क्लास में URL-सुरक्षित मोड नहीं है। हाल के .NET संस्करण System.Buffers.Text में एक समर्पित Base64Url क्लास जोड़ते हैं, और ASP.NET Core WebEncoders.Base64UrlEncode देता है। अगर दोनों उपलब्ध नहीं हैं, तो हाथ से बदलें:

string url = Convert.ToBase64String(bytes) .TrimEnd('=') .Replace('+', '-') .Replace('/', '_');

एक और जाल: .NET में Encoding.Unicode UTF-16 है, UTF-8 नहीं। इसका उपयोग करने से ऐसा Base64 बनता है जो अधिकांश अन्य भाषाओं से अलग है।

Go

encoding/base64 पैकेज तैयार एन्कोडिंग को वेरिएबल के रूप में देता है, इसलिए अक्षर-समूह और पैडिंग का चुनाव स्पष्ट रहता है:

import "encoding/base64" encoded := base64.StdEncoding.EncodeToString([]byte("Hello, World!")) // SGVsbG8sIFdvcmxkIQ== decoded, err := base64.StdEncoding.DecodeString(encoded) if err != nil { // invalid input } text := string(decoded)

चार मानक एन्कोडिंग ये हैं:

  • StdEncoding: मानक अक्षर-समूह, पैडिंग के साथ।
  • URLEncoding: URL-सुरक्षित अक्षर-समूह, पैडिंग के साथ।
  • RawStdEncoding: मानक अक्षर-समूह, बिना पैडिंग।
  • RawURLEncoding: URL-सुरक्षित अक्षर-समूह, बिना पैडिंग। JWT लाइब्रेरी यही उपयोग करती हैं।

Go सख़्त है। जिस स्ट्रिंग की पैडिंग हटा दी गई हो उसे StdEncoding से डिकोड करने पर illegal base64 data at input byte N जैसी त्रुटि आती है, इसलिए आपको वही एन्कोडिंग चुननी होगी जो आपके डेटा से ठीक मेल खाती हो।

PHP

PHP में दो बिल्ट-इन फ़ंक्शन हैं:

$encoded = base64_encode('Hello, World!'); // SGVsbG8sIFdvcmxkIQ== $decoded = base64_decode($encoded, true); if ($decoded === false) { // invalid input }

base64_decode के दूसरे तर्क के रूप में हमेशा true दें। इसके बिना PHP अक्षर-समूह से बाहर के अक्षरों को चुपचाप अनदेखा कर देता है, इसलिए गलत इनपुट त्रुटि के बजाय कचरा नतीजा दे सकता है। सख़्त मोड में अमान्य इनपुट पर फ़ंक्शन false लौटाता है।

PHP में URL-सुरक्षित बिल्ट-इन फ़ंक्शन नहीं हैं, इसलिए strtr का उपयोग करें:

function base64url_encode(string $data): string { return rtrim(strtr(base64_encode($data), '+/', '-_'), '='); } function base64url_decode(string $data): string|false { return base64_decode(strtr($data, '-_', '+/')); }

व्यवहार के अंतर एक नज़र में

  • डिकोड करते समय पैडिंग: Java का URL डिकोडर गायब पैडिंग स्वीकार करता है, Go आपसे Raw एन्कोडिंग चुनवाता है, और .NET का FromBase64String सही पैडिंग की अपेक्षा करता है।
  • खाली स्थान: Java का MIME डिकोडर लाइन ब्रेक को अनदेखा करता है; Java, Go और .NET के मानक डिकोडर अधिकांश मामलों में स्पेस अस्वीकार करते हैं; PHP गैर-सख़्त मोड में उन्हें छोड़ देता है।
  • त्रुटियाँ: Java IllegalArgumentException फेंकता है, .NET FormatException फेंकता है, Go error लौटाता है और PHP सख़्त मोड में false लौटाता है।

ऊपर के संदेशों की पहचान में मदद के लिए आम Base64 त्रुटियाँ और उन्हें ठीक करने के तरीके पढ़ें।
