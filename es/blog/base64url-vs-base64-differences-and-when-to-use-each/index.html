Base64URL frente a Base64: diferencias y cuándo usar cada uno

Agosto de 20264 min de lectura

Si has trabajado con tokens JWT, OAuth 2.0 o parámetros de URL, probablemente te hayas encontrado con Base64URL, una variante del Base64 estándar que se parece muchísimo pero se comporta de forma distinta en ciertos contextos. Entender la diferencia puede ahorrarte horas depurando errores de codificación crípticos.

¿Qué es el Base64 estándar?

El Base64 estándar, definido en el RFC 4648 §4, codifica datos binarios usando 64 caracteres: A–Z, a–z, 0–9, más (+) y barra (/). La salida se rellena con signos igual (=) para que la longitud sea múltiplo de 4. Por ejemplo, codificar "Man" da "TWFu".

El problema surge cuando intentas usar una cadena Base64 estándar en una URL. El carácter + se interpreta como un espacio en las cadenas de consulta de URL, y / es un separador de ruta. Una cadena Base64 como "abc+def/ghi=" colocada en una URL será interpretada incorrectamente por servidores web y navegadores.

¿Qué es Base64URL?

Base64URL, definido en el RFC 4648 §5, resuelve esto haciendo dos sustituciones:

  • + se reemplaza por - (guion)
  • / se reemplaza por _ (guion bajo)
  • el padding = se omite por completo

Todos estos caracteres son seguros en URLs y nombres de archivo sin necesidad de codificación por porcentaje. El mismo ejemplo "Man" se codifica como "TWFu" en ambas variantes (no hay caracteres especiales en este caso), pero una cadena como "i+Uo/A==" en Base64 estándar se convierte en "i-Uo_A" en Base64URL.

Los tokens JWT usan Base64URL

Los JSON Web Tokens (JWT) son el lugar donde los desarrolladores encuentran Base64URL con más frecuencia. Un JWT consta de tres partes separadas por puntos: header.payload.signature. Tanto el header como el payload están codificados en Base64URL, no en Base64 estándar. Por eso las cadenas JWT contienen guiones y guiones bajos, pero nunca signos más ni barras.

Si pegas un JWT en un decodificador Base64 estándar sin convertir antes los caracteres, obtendrás un error de decodificación o una salida ilegible. Usa siempre un decodificador compatible con Base64URL para los JWT.

Convertir entre ambos

Para convertir una cadena Base64 estándar a Base64URL:

  1. Reemplaza todos los + por -
  2. Reemplaza todas las / por _
  3. Elimina todos los caracteres de padding =

Para convertir Base64URL de vuelta a Base64 estándar:

  1. Reemplaza todos los - por +
  2. Reemplaza todos los _ por /
  3. Añade padding = hasta que la longitud de la cadena sea múltiplo de 4

Cuándo usar cada variante

Usa Base64 estándar cuando:

  • Codifiques adjuntos de correo (MIME, RFC 2045)
  • Incrustes imágenes como Data URIs en HTML y CSS
  • Almacenes datos binarios en payloads JSON o XML donde el valor va entre comillas
  • Trabajes con sistemas que requieran específicamente Base64 estándar

Usa Base64URL cuando:

  • Generes o analices tokens JWT
  • Crees tokens seguros para URL para los desafíos PKCE de OAuth 2.0
  • Codifiques datos para parámetros de consulta de URL o segmentos de ruta
  • Crees nombres de archivo a partir de datos binarios (los nombres de archivo no pueden contener / en la mayoría de sistemas)
  • Trabajes con APIs de criptografía web, que normalmente producen Base64URL

Codificar con la variante adecuada

En encodeb64.com puedes alternar entre Base64 estándar y Base64URL usando la casilla "URL-safe encoding (Base64URL)" en las opciones avanzadas. La herramienta aplica automáticamente las sustituciones de caracteres y elimina el padding cuando esta opción está activada. Para decodificar cualquiera de las dos variantes, usa decodeb64.com.

La diferencia entre Base64 y Base64URL es pequeña pero importante. Ante la duda, revisa la especificación del sistema con el que estás integrando: JWT siempre significa Base64URL, mientras que MIME siempre significa Base64 estándar con saltos de línea. Usar la variante equivocada es una de las causas más comunes de errores de codificación en aplicaciones web.
