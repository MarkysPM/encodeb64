Base64 en ligne de commande : Linux, macOS et Windows

Novembre 20266 min de lecture

Vous n'avez besoin ni d'un site web ni d'un script pour travailler avec Base64. Tous les grands systèmes d'exploitation fournissent des outils capables de l'encoder et de le décoder depuis le terminal, ce qui est pratique pour inspecter des jetons, créer des secrets pour des fichiers de configuration ou convertir de petits fichiers. Ce guide couvre Linux, macOS et Windows, et signale les différences qui causent des résultats déroutants.

Linux : la commande base64

La commande GNU base64 fait partie de coreutils et est installée sur pratiquement toutes les distributions Linux.

Encoder une chaîne :

echo -n 'Hello, World!' | base64 # SGVsbG8sIFdvcmxkIQ==

La décoder :

echo 'SGVsbG8sIFdvcmxkIQ==' | base64 --decode # Hello, World!

Encoder et décoder des fichiers :

base64 photo.png > photo.b64 base64 --decode photo.b64 > photo-copy.png

Le piège du saut de ligne final

C'est l'erreur la plus courante. Un echo simple ajoute un caractère de saut de ligne à sa sortie, et ce saut de ligne fait alors partie des données encodées :

echo 'Hello' | base64 # SGVsbG8K (encodes "Hello\n") echo -n 'Hello' | base64 # SGVsbG8= (encodes "Hello")

Si un mot de passe, une clé d'API ou un jeton « ne marche pas » après avoir été encodé dans le terminal, un saut de ligne en trop est le coupable probable. Utilisez toujours echo -n, ou printf '%s' 'Hello', qui se comporte de la même façon dans tous les shells.

Retour à la ligne automatique

La commande base64 de GNU coupe sa sortie tous les 76 caractères. C'est acceptable pour des fichiers, mais pas pour un collage dans du JSON, des variables d'environnement ou des en-têtes HTTP. Désactivez ce découpage avec -w 0 :

base64 -w 0 photo.png

macOS

macOS inclut une version BSD de base64 qui accepte des options légèrement différentes. L'encodage de base avec un tube fonctionne de la même manière :

echo -n 'Hello, World!' | base64 echo 'SGVsbG8sIFdvcmxkIQ==' | base64 --decode

Utilisez -i pour un fichier d'entrée et -o pour un fichier de sortie :

base64 -i photo.png -o photo.b64

L'option GNU -w 0 n'existe pas sur macOS, et les anciennes versions de macOS utilisaient -D au lieu de -d ou --decode. Si un script doit fonctionner sur les deux systèmes, testez la plateforme ou utilisez openssl, présenté ci-dessous.

openssl : l'option portable

OpenSSL est disponible sous Linux, macOS et Windows (via Git for Windows ou WSL) et se comporte de façon cohérente :

echo -n 'Hello, World!' | openssl base64 echo 'SGVsbG8sIFdvcmxkIQ==' | openssl base64 -d openssl base64 -in photo.png -out photo.b64

Ajoutez -A pour garder la sortie sur une seule ligne au lieu de la découper.

Windows PowerShell

PowerShell peut appeler directement la classe Convert de .NET. Encoder du texte :

[Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes('Hello, World!')) # SGVsbG8sIFdvcmxkIQ==

Décoder du texte :

[Text.Encoding]::UTF8.GetString([Convert]::FromBase64String('SGVsbG8sIFdvcmxkIQ==')) # Hello, World!

Encoder un fichier en chaîne Base64 :

[Convert]::ToBase64String([IO.File]::ReadAllBytes('photo.png'))

Décoder une chaîne Base64 vers un fichier :

[IO.File]::WriteAllBytes('photo-copy.png', [Convert]::FromBase64String($base64))

Remarquez que vous choisissez explicitement l'encodage du texte (UTF8). Si vous utilisez Unicode à la place, PowerShell emploie UTF-16 et le résultat différera de celui de Linux et de macOS.

Windows certutil

L'ancien outil certutil fonctionne depuis l'invite de commandes sur tout système Windows :

certutil -encode photo.png photo.b64 certutil -decode photo.b64 photo-copy.png

Sachez que certutil -encode entoure la sortie de lignes d'en-tête et de pied -----BEGIN CERTIFICATE-----. Supprimez ces lignes si vous n'avez besoin que du texte Base64.

Décoder du Base64URL depuis le terminal

Les JWT et de nombreuses API modernes utilisent l'alphabet adapté aux URL et omettent le remplissage ; un simple base64 --decode peut donc échouer. Convertissez d'abord les caractères et rétablissez le remplissage :

value='eyJhbGciOiJIUzI1NiJ9' len=$(( ${#value} % 4 )) [ $len -eq 2 ] && value="$value==" [ $len -eq 3 ] && value="$value=" echo "$value" | tr '_-' '/+' | base64 --decode # {"alg":"HS256"}

Pour comprendre pourquoi ces jetons ont un aspect différent, lisez Comment les jetons JWT utilisent l'encodage Base64URL.

Comparaison rapide

  • Linux : base64, avec -w 0 pour une seule ligne.
  • macOS : base64 avec -i et -o ; pas d'option -w.
  • Multiplateforme : openssl base64.
  • Windows : [Convert] de PowerShell ou certutil.
