Java, C#, Go, PHP의 Base64: 코드 예제

2026년 11월읽는 시간 약 7분

주요 언어에는 모두 Base64 지원이 내장되어 있지만, 이름, 기본값, 실패 시 동작이 달라 실제 버그를 일으킵니다. 특히 URL 안전 출력, 패딩, 잘못된 입력에서 그렇습니다. 이 가이드는 Java, C#, Go, PHP의 간결하고 복사해 쓸 수 있는 예제를 제공하고 알아둘 만한 차이를 짚어 줍니다. JavaScript와 Python은 JavaScript 가이드와 Python 가이드를 참고하세요.

이 예제들이 사용하는 테스트 문자열

모든 예제는 텍스트 Hello, World!를 인코딩하며, 어떤 언어에서든 같은 결과가 나와야 합니다.

SGVsbG8sIFdvcmxkIQ==

출력이 다르다면 문자 인코딩을 확인하세요. 인코딩하기 전에 항상 텍스트를 UTF-8 바이트로 변환하세요. 그렇지 않으면 ASCII가 아닌 텍스트에서 플랫폼마다 결과가 달라집니다.

Java

Java 8부터 java.util.Base64 클래스가 표준 도구입니다. 새 코드에서는 오래된 sun.misc.BASE64Encoder와 서드파티 헬퍼를 피하세요.

import java.util.Base64; import java.nio.charset.StandardCharsets; String encoded = Base64.getEncoder() .encodeToString("Hello, World!".getBytes(StandardCharsets.UTF_8)); // SGVsbG8sIFdvcmxkIQ== byte[] decoded = Base64.getDecoder().decode(encoded); String text = new String(decoded, StandardCharsets.UTF_8);

Java는 세 가지 인코더·디코더 계열을 제공합니다.

  • getEncoder()와 getDecoder(): 표준 Base64.
  • getUrlEncoder()와 getUrlDecoder(): URL 안전 문자 집합.
  • getMimeEncoder()와 getMimeDecoder(): MIME. 76자마다 줄바꿈하며 디코딩 시 줄바꿈을 무시합니다.

JWT처럼 = 패딩을 없애려면 withoutPadding()을 이어 붙입니다.

String token = Base64.getUrlEncoder().withoutPadding() .encodeToString("subjects?_d".getBytes(StandardCharsets.UTF_8)); // c3ViamVjdHM_X2Q

잘못된 입력은 IllegalArgumentException을 던집니다. 예를 들어 공백이 들어 있는 문자열을 표준 디코더로 디코딩하면 Illegal base64 character 20(공백의 16진수 코드) 같은 메시지와 함께 실패합니다. 입력에 줄바꿈이 포함될 수 있다면 getMimeDecoder()를 쓰세요.

C#과 .NET

Convert 클래스가 표준 Base64를 처리합니다.

using System; using System.Text; string encoded = Convert.ToBase64String(Encoding.UTF8.GetBytes("Hello, World!")); // SGVsbG8sIFdvcmxkIQ== byte[] decoded = Convert.FromBase64String(encoded); string text = Encoding.UTF8.GetString(decoded);

Convert.FromBase64String은 잘못된 입력에 FormatException을 던집니다. 성능이 중요한 경로에서 예외를 피하려면, 미리 할당한 버퍼와 함께 Convert.TryFromBase64String을 쓰는 예외 없는 방식을 사용하세요.

기존 Convert 클래스에는 URL 안전 모드가 없습니다. 최신 .NET은 System.Buffers.Text에 전용 Base64Url 클래스를 추가했고, ASP.NET Core도 WebEncoders.Base64UrlEncode를 제공합니다. 둘 다 쓸 수 없다면 직접 변환하세요.

string url = Convert.ToBase64String(bytes) .TrimEnd('=') .Replace('+', '-') .Replace('/', '_');

또 하나의 함정: .NET의 Encoding.Unicode는 UTF-8이 아니라 UTF-16입니다. 이를 사용하면 대부분의 다른 언어와 다른 Base64가 만들어집니다.

Go

encoding/base64 패키지는 미리 만들어진 인코딩을 변수로 제공하므로 문자 집합과 패딩의 선택이 명시적입니다.

import "encoding/base64" encoded := base64.StdEncoding.EncodeToString([]byte("Hello, World!")) // SGVsbG8sIFdvcmxkIQ== decoded, err := base64.StdEncoding.DecodeString(encoded) if err != nil { // invalid input } text := string(decoded)

표준 인코딩 네 가지는 다음과 같습니다.

  • StdEncoding: 표준 문자 집합, 패딩 있음.
  • URLEncoding: URL 안전 문자 집합, 패딩 있음.
  • RawStdEncoding: 표준 문자 집합, 패딩 없음.
  • RawURLEncoding: URL 안전 문자 집합, 패딩 없음. JWT 라이브러리가 사용하는 것이 이것입니다.

Go는 엄격합니다. 패딩이 제거된 문자열을 StdEncoding으로 디코딩하면 illegal base64 data at input byte N 같은 오류로 실패하므로, 데이터와 정확히 맞는 인코딩을 골라야 합니다.

PHP

PHP에는 두 가지 내장 함수가 있습니다.

$encoded = base64_encode('Hello, World!'); // SGVsbG8sIFdvcmxkIQ== $decoded = base64_decode($encoded, true); if ($decoded === false) { // invalid input }

base64_decode의 두 번째 인수로는 항상 true를 전달하세요. 그렇지 않으면 PHP가 문자 집합 밖의 문자를 조용히 무시하므로, 잘못된 입력이 오류 대신 쓰레기 값을 만들 수 있습니다. 엄격 모드에서는 잘못된 입력에 대해 함수가 false를 반환합니다.

PHP에는 URL 안전 내장 함수가 없으므로 strtr을 사용하세요.

function base64url_encode(string $data): string { return rtrim(strtr(base64_encode($data), '+/', '-_'), '='); } function base64url_decode(string $data): string|false { return base64_decode(strtr($data, '-_', '+/')); }

동작 차이 한눈에 보기

  • 디코딩 시 패딩: Java의 URL 디코더는 패딩이 없어도 받아들이고, Go는 Raw 인코딩을 골라야 하며, .NET의 FromBase64String은 올바른 패딩을 기대합니다.
  • 공백 문자: Java의 MIME 디코더는 줄바꿈을 무시하고, Java·Go·.NET의 표준 디코더는 대부분의 경우 공백을 거부하며, PHP는 비엄격 모드에서 공백을 버립니다.
  • 오류: Java는 IllegalArgumentException, .NET은 FormatException을 던지고, Go는 error를 반환하며, PHP는 엄격 모드에서 false를 반환합니다.

위 메시지를 진단하는 데 도움이 필요하다면 자주 발생하는 Base64 오류와 해결 방법을 읽어 보세요.
