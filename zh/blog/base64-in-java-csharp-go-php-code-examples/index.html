Java、C#、Go 和 PHP 中的 Base64：代码示例

2026年11月阅读时间约 7 分钟

每种主流语言都内置了 Base64 支持，但名称、默认值和失败时的行为各不相同，这些差异会引发真实的 bug，尤其是在 URL 安全输出、填充和无效输入方面。本文为 Java、C#、Go 和 PHP 提供简洁、可直接复制的示例，并指出值得了解的差异。JavaScript 和 Python 请参阅我们的 JavaScript 与 Python 指南。

这些示例使用的测试字符串

所有示例都对文本 Hello, World! 编码，在每种语言中结果都应相同：

SGVsbG8sIFdvcmxkIQ==

如果你的输出不同，请检查字符编码。编码前务必先把文本转换为 UTF-8 字节；否则对于非 ASCII 文本，不同平台的结果会不一致。

Java

自 Java 8 起，java.util.Base64 类就是标准工具。新代码中请避免使用旧的 sun.misc.BASE64Encoder 和第三方辅助类。

import java.util.Base64; import java.nio.charset.StandardCharsets; String encoded = Base64.getEncoder() .encodeToString("Hello, World!".getBytes(StandardCharsets.UTF_8)); // SGVsbG8sIFdvcmxkIQ== byte[] decoded = Base64.getDecoder().decode(encoded); String text = new String(decoded, StandardCharsets.UTF_8);

Java 提供三组编码器和解码器：

  • getEncoder() 和 getDecoder()：标准 Base64。
  • getUrlEncoder() 和 getUrlDecoder()：URL 安全字符集。
  • getMimeEncoder() 和 getMimeDecoder()：MIME，每 76 个字符换行，解码时忽略换行符。

要去掉 = 填充（JWT 就是这样做的），链式调用 withoutPadding()：

String token = Base64.getUrlEncoder().withoutPadding() .encodeToString("subjects?_d".getBytes(StandardCharsets.UTF_8)); // c3ViamVjdHM_X2Q

无效输入会抛出 IllegalArgumentException。例如，用标准解码器解码含空格的字符串会失败，并给出类似 Illegal base64 character 20 的消息（20 是空格的十六进制代码）。如果输入可能包含换行，请改用 getMimeDecoder()。

C# 与 .NET

Convert 类负责标准 Base64：

using System; using System.Text; string encoded = Convert.ToBase64String(Encoding.UTF8.GetBytes("Hello, World!")); // SGVsbG8sIFdvcmxkIQ== byte[] decoded = Convert.FromBase64String(encoded); string text = Encoding.UTF8.GetString(decoded);

遇到无效输入时，Convert.FromBase64String 会抛出 FormatException。要在性能关键路径中避免异常，请使用不抛异常的写法：Convert.TryFromBase64String 配合预先分配的缓冲区。

经典的 Convert 类没有 URL 安全模式。较新的 .NET 版本在 System.Buffers.Text 中新增了专门的 Base64Url 类，ASP.NET Core 也提供了 WebEncoders.Base64UrlEncode。如果两者都用不了，就手动转换：

string url = Convert.ToBase64String(bytes) .TrimEnd('=') .Replace('+', '-') .Replace('/', '_');

还有一个陷阱：.NET 中的 Encoding.Unicode 是 UTF-16，而不是 UTF-8。使用它得到的 Base64 与大多数其他语言不同。

Go

encoding/base64 包以变量的形式提供现成的编码，因此字符集和填充的选择是显式的：

import "encoding/base64" encoded := base64.StdEncoding.EncodeToString([]byte("Hello, World!")) // SGVsbG8sIFdvcmxkIQ== decoded, err := base64.StdEncoding.DecodeString(encoded) if err != nil { // invalid input } text := string(decoded)

四种标准编码是：

  • StdEncoding：标准字符集，带填充。
  • URLEncoding：URL 安全字符集，带填充。
  • RawStdEncoding：标准字符集，无填充。
  • RawURLEncoding：URL 安全字符集，无填充。JWT 库使用的就是这种。

Go 很严格。用 StdEncoding 解码被去掉填充的字符串会失败，并报出类似 illegal base64 data at input byte N 的错误，所以你必须选择与数据完全匹配的编码。

PHP

PHP 有两个内置函数：

$encoded = base64_encode('Hello, World!'); // SGVsbG8sIFdvcmxkIQ== $decoded = base64_decode($encoded, true); if ($decoded === false) { // invalid input }

调用 base64_decode 时，务必把第二个参数设为 true。否则 PHP 会悄悄忽略字符集之外的字符，因此格式错误的输入可能产生乱码而不是报错。在严格模式下，遇到无效输入函数会返回 false。

PHP 没有内置的 URL 安全函数，所以使用 strtr：

function base64url_encode(string $data): string { return rtrim(strtr(base64_encode($data), '+/', '-_'), '='); } function base64url_decode(string $data): string|false { return base64_decode(strtr($data, '-_', '+/')); }

行为差异一览

  • 解码时的填充：Java 的 URL 解码器接受缺失的填充，Go 要求你选择 Raw 编码，.NET 的 FromBase64String 则要求填充正确。
  • 空白字符：Java 的 MIME 解码器会忽略换行；Java、Go 和 .NET 的标准解码器在多数情况下会拒绝空格；PHP 在非严格模式下会丢弃它们。
  • 错误：Java 抛出 IllegalArgumentException，.NET 抛出 FormatException，Go 返回 error，PHP 在严格模式下返回 false。

想了解上述消息的排查方法，请阅读常见 Base64 错误及修复方法。
