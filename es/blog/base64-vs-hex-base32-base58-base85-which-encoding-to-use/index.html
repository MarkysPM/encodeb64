Base64 vs Hex vs Base32 vs Base85: ¿cuál usar?

Noviembre de 20267 min de lectura

Cuando necesitas representar datos binarios como texto, Base64 es la opción por defecto, pero ni de lejos la única. Hexadecimal, Base32, Base58 y Base85 resuelven el mismo problema con distintos compromisos de tamaño, legibilidad y seguridad. Elegir mal da cargas infladas, errores de mayúsculas y minúsculas o cadenas que las personas no pueden teclear bien. Esta guía los compara con mediciones reales y te da una forma sencilla de elegir.

La idea central: bits por carácter

Toda codificación de bytes a texto se define con un número: cuántos bits de datos lleva cada carácter de salida. Un alfabeto más grande lleva más bits por carácter y produce una salida más corta.

  • Hex (Base16) tiene 16 símbolos, así que cada carácter lleva 4 bits.
  • Base32 tiene 32 símbolos, así que cada carácter lleva 5 bits.
  • Base64 tiene 64 símbolos, así que cada carácter lleva 6 bits.
  • Base85 tiene 85 símbolos, así que de media cada carácter lleva algo más de 6,4 bits.

El precio de un alfabeto mayor es que incluye más signos de puntuación y mezcla de mayúsculas y minúsculas, lo que es más difícil de leer en voz alta o teclear, y más fácil de dañar por sistemas que cambian las mayúsculas o tratan los símbolos de forma especial.

Sobrecarga de tamaño medida

Para compararlos con justicia, codifiqué 1000 bytes aleatorios con la biblioteca estándar de Python y conté los caracteres de salida:

  • Hex (Base16): 2000 caracteres (+100 %)
  • Base32: 1600 caracteres (+60 %)
  • Base64: 1336 caracteres (+33,6 %)
  • Base85 / Ascii85: 1250 caracteres (+25 %)

Base58 no es un alfabeto de potencia de dos, así que su longitud depende de los datos, pero en la práctica queda entre Base64 y Base32, con una sobrecarga de alrededor del 37 %.

Hex (Base16)

Hex escribe cada byte con dos caracteres de 0-9 y a-f. Es la opción menos eficiente, pero también la más fácil de leer, porque un byte siempre corresponde exactamente a dos caracteres y se ven los valores de cada byte.

Hello → 48656c6c6f

Úsalo para: hashes y sumas de verificación (los resúmenes SHA-256 casi siempre se muestran en hex), colores, direcciones MAC, volcados de depuración y todo lo que una persona deba inspeccionar byte a byte. En la práctica también es inmune a problemas de mayúsculas y símbolos, porque solo usa dígitos y letras.

Base32

Base32 usa las letras A-Z y los dígitos 2-7. Se diseñó para ser seguro en sistemas que no distinguen mayúsculas de minúsculas y para evitar caracteres parecidos, como 0 y O o 1 e I.

Hello → JBSWY3DP

Úsalo para: valores que las personas tienen que teclear o leer en voz alta, y valores guardados en lugares que no distinguen mayúsculas, como algunos sistemas de archivos y nombres DNS. El ejemplo más conocido es la clave secreta que ves al configurar la autenticación en dos pasos con una app de autenticación. La salida se rellena con = hasta un múltiplo de ocho caracteres.

Base64

Base64 usa A-Z, a-z, 0-9, + y /. Es el mejor equilibrio general entre compacidad y soporte universal: todos los lenguajes lo incluyen y es el formato que esperan el correo, las URI de datos, las API JSON y muchos protocolos.

Hello → SGVsbG8=

Úsalo para: incrustar archivos en JSON, XML, HTML y CSS, adjuntos de correo, claves y certificados criptográficos en archivos PEM, y la mayoría de las API que transportan datos binarios. La variante segura para URL, Base64URL, cambia + y / por - y _; consulta Base64URL vs Base64.

Base58

Base58 es Base64 sin los caracteres que se confunden: omite 0 (cero), O (o mayúscula), I (i mayúscula), l (ele minúscula) y los símbolos + y /. El resultado es una cadena fácil de copiar a mano y que se puede seleccionar con doble clic en la mayoría de programas, porque no tiene signos de puntuación.

Úsalo para: identificadores que las personas transcriben, como direcciones de criptomonedas y algunos ID cortos. Su desventaja es que, a diferencia de los alfabetos de potencia de dos, codificar y decodificar requiere aritmética de números grandes, así que es más lento y no sirve para datos grandes. Además no forma parte de la mayoría de bibliotecas estándar, por lo que normalmente necesitas un paquete.

Base85 (Ascii85)

Base85 empaqueta cuatro bytes en cinco caracteres, lo que da la menor sobrecarga de las codificaciones de texto aquí: 25 %. Usa un alfabeto grande con muchos símbolos, lo que lo hace compacto pero incómodo donde la puntuación tiene significado especial.

Úsalo para: formatos donde importa el espacio y el medio está controlado, como PDF y PostScript. Git usa una variante para incrustar parches binarios. Python ofrece base64.a85encode() y base64.b85encode(), pero el soporte en otros lenguajes es menos universal que el de Base64.

Una guía rápida para decidir

  • ¿Una persona leerá los bytes (hashes, depuración)? Usa hex.
  • ¿Una persona tecleará o dirá el valor en voz alta, o debe sobrevivir a un cambio de mayúsculas? Usa Base32 (o Base58 si se conservan las mayúsculas).
  • ¿Las máquinas intercambian datos binarios por API de texto, JSON, HTML o correo? Usa Base64.
  • ¿El valor va en una URL, un nombre de archivo o un JWT? Usa Base64URL.
  • ¿Cada byte cuenta y controlas ambos extremos? Considera Base85 o, mejor, evita la codificación de texto y envía bytes crudos.

A veces la mejor codificación es ninguna

Todas las codificaciones anteriores añaden sobrecarga. Si tu protocolo puede transportar bytes crudos, como una subida binaria con multipart/form-data, una columna binaria en una base de datos o gRPC, úsalo. Recurre a una codificación de texto solo cuando el canal te obligue.
