Base64 auf der Kommandozeile: Linux, macOS und Windows

November 20266 Min. Lesezeit

Für Base64 brauchen Sie weder eine Website noch ein Skript. Alle gängigen Betriebssysteme liefern Werkzeuge mit, die es im Terminal kodieren und dekodieren können. Das ist praktisch, um Tokens zu untersuchen, Geheimnisse für Konfigurationsdateien zu erzeugen oder kleine Dateien umzuwandeln. Dieser Leitfaden behandelt Linux, macOS und Windows und weist auf die Unterschiede hin, die zu verwirrenden Ergebnissen führen.

Linux: der Befehl base64

Der GNU-Befehl base64 gehört zu coreutils und ist auf praktisch jeder Linux-Distribution installiert.

Eine Zeichenkette kodieren:

echo -n 'Hello, World!' | base64 # SGVsbG8sIFdvcmxkIQ==

Wieder dekodieren:

echo 'SGVsbG8sIFdvcmxkIQ==' | base64 --decode # Hello, World!

Dateien kodieren und dekodieren:

base64 photo.png > photo.b64 base64 --decode photo.b64 > photo-copy.png

Die Falle mit dem abschließenden Zeilenumbruch

Das ist der häufigste Fehler. Ein einfaches echo hängt einen Zeilenumbruch an seine Ausgabe an, und dieser Zeilenumbruch wird Teil der kodierten Daten:

echo 'Hello' | base64 # SGVsbG8K (encodes "Hello\n") echo -n 'Hello' | base64 # SGVsbG8= (encodes "Hello")

Wenn ein Passwort, API-Schlüssel oder Token nach dem Kodieren im Terminal „nicht funktioniert“, ist ein zusätzlicher Zeilenumbruch der wahrscheinlichste Grund. Verwenden Sie immer echo -n oder printf '%s' 'Hello', das sich in jeder Shell gleich verhält.

Zeilenumbruch in der Ausgabe

Das GNU-base64 bricht seine Ausgabe nach 76 Zeichen um. Für Dateien ist das in Ordnung, nicht aber zum Einfügen in JSON, Umgebungsvariablen oder HTTP-Header. Deaktivieren Sie den Umbruch mit -w 0:

base64 -w 0 photo.png

macOS

macOS enthält eine BSD-Version von base64, die leicht abweichende Optionen akzeptiert. Die einfache Kodierung über eine Pipe funktioniert genauso:

echo -n 'Hello, World!' | base64 echo 'SGVsbG8sIFdvcmxkIQ==' | base64 --decode

Verwenden Sie -i für eine Eingabedatei und -o für eine Ausgabedatei:

base64 -i photo.png -o photo.b64

Die GNU-Option -w 0 gibt es unter macOS nicht, und ältere macOS-Versionen verwendeten -D statt -d oder --decode. Muss ein Skript auf beiden Systemen laufen, prüfen Sie die Plattform oder nutzen Sie das unten beschriebene openssl.

openssl: die portable Option

OpenSSL ist unter Linux, macOS und Windows (über Git for Windows oder WSL) verfügbar und verhält sich einheitlich:

echo -n 'Hello, World!' | openssl base64 echo 'SGVsbG8sIFdvcmxkIQ==' | openssl base64 -d openssl base64 -in photo.png -out photo.b64

Fügen Sie -A hinzu, um die Ausgabe in einer einzigen Zeile zu halten, statt sie umzubrechen.

Windows PowerShell

PowerShell kann die .NET-Klasse Convert direkt aufrufen. Text kodieren:

[Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes('Hello, World!')) # SGVsbG8sIFdvcmxkIQ==

Text dekodieren:

[Text.Encoding]::UTF8.GetString([Convert]::FromBase64String('SGVsbG8sIFdvcmxkIQ==')) # Hello, World!

Eine Datei in eine Base64-Zeichenkette kodieren:

[Convert]::ToBase64String([IO.File]::ReadAllBytes('photo.png'))

Eine Base64-Zeichenkette wieder in eine Datei schreiben:

[IO.File]::WriteAllBytes('photo-copy.png', [Convert]::FromBase64String($base64))

Beachten Sie, dass Sie die Textkodierung ausdrücklich wählen (UTF8). Verwenden Sie stattdessen Unicode, nutzt PowerShell UTF-16, und das Ergebnis unterscheidet sich von dem unter Linux und macOS.

Windows certutil

Das ältere Werkzeug certutil funktioniert in der Eingabeaufforderung auf jedem Windows-System:

certutil -encode photo.png photo.b64 certutil -decode photo.b64 photo-copy.png

Beachten Sie, dass certutil -encode die Ausgabe mit den Kopf- und Fußzeilen -----BEGIN CERTIFICATE----- umgibt. Entfernen Sie diese Zeilen, wenn Sie nur den Base64-Text benötigen.

Base64URL im Terminal dekodieren

JWTs und viele moderne APIs nutzen das URL-sichere Alphabet und lassen das Padding weg, daher kann ein einfaches base64 --decode fehlschlagen. Wandeln Sie zuerst die Zeichen um und stellen Sie das Padding wieder her:

value='eyJhbGciOiJIUzI1NiJ9' len=$(( ${#value} % 4 )) [ $len -eq 2 ] && value="$value==" [ $len -eq 3 ] && value="$value=" echo "$value" | tr '_-' '/+' | base64 --decode # {"alg":"HS256"}

Warum diese Tokens anders aussehen, erklärt Wie JWT-Tokens die Base64URL-Kodierung verwenden.

Schneller Vergleich

  • Linux: base64, mit -w 0 für eine einzige Zeile.
  • macOS: base64 mit -i und -o; keine Option -w.
  • Plattformübergreifend: openssl base64.
  • Windows: PowerShell-[Convert] oder certutil.
