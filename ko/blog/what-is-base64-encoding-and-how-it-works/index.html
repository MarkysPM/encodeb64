Base64 인코딩이란 무엇이며 어떻게 동작할까?

2026년 11월읽는 시간 약 7분

Base64는 인쇄 가능한 64개의 문자만으로 바이너리 데이터를 표현하는 방식입니다. 이메일 첨부 파일, JSON 페이로드, HTML과 CSS의 data URI, HTTP 헤더, JWT 토큰, 설정 파일처럼 텍스트만 이해하는 경로로 바이트를 옮겨야 하는 곳이면 어디서나 쓰입니다. 이렇게 흔한데도 Base64는 종종 블랙박스처럼 취급됩니다. 이 가이드에서는 Base64가 정확히 무엇을 하는지 한 단계씩 설명합니다.

Base64가 필요한 이유

많은 프로토콜은 임의의 바이트가 아니라 텍스트를 전제로 설계되었습니다. 초기 이메일 시스템(SMTP)이 보장한 것은 7비트 ASCII 텍스트가 온전히 전달된다는 사실뿐이었습니다. JPEG, PDF, 암호화된 데이터에는 제어 문자, 줄 바꿈, 메시지 종료 표시와 혼동될 수 있는 바이트 값이 들어 있고, 전송 과정에서 이런 값이 조용히 바뀌거나 거부될 수 있습니다.

Base64는 임의의 바이트열을 영문자, 숫자, +, /로만 이루어진 문자열로 바꿔 이 문제를 해결합니다. 이 문자들은 거의 모든 텍스트 경로를 변하지 않고 통과합니다. 수신자는 과정을 거꾸로 수행해 원래 바이트를 정확히 복원합니다.

Base64 알파벳

표준 알파벳(RFC 4648)의 64개 문자는 다음과 같습니다.

  • 값 0–25: A부터 Z
  • 값 26–51: a부터 z
  • 값 52–61: 0부터 9
  • 값 62: +
  • 값 63: /

65번째 문자인 =는 출력 끝의 패딩으로만 사용됩니다.

알고리즘의 동작 방식

1바이트는 8비트지만 Base64 문자 하나가 나타낼 수 있는 것은 6비트(26 = 64가지 값)뿐입니다. 그래서 알고리즘은 입력 비트를 다시 묶습니다.

  1. 입력을 3바이트(24비트)씩 가져옵니다.
  2. 그 24비트를 6비트씩 네 그룹으로 나눕니다.
  3. 각 6비트 값을 알파벳에서 찾아 네 개의 출력 문자를 얻습니다.

입력 3바이트가 출력 4문자가 됩니다. 이 비율이 아래에서 다룰 크기 증가의 이유입니다.

예제: “Man” 인코딩하기

텍스트 Man은 ASCII로 3바이트입니다. M = 77, a = 97, n = 110입니다. 이진수로 쓰면 다음과 같습니다.

M = 01001101 a = 01100001 n = 01101110

24비트를 이어 붙인 뒤 6비트씩 네 그룹으로 나눕니다.

010011 010110 000101 101110

이 그룹들은 숫자 19, 22, 5, 46에 해당합니다. 알파벳에서 찾으면 T, W, F, u입니다. 즉:

Man → TWFu

Man을 홈페이지의 인코더에 붙여 넣어 확인해 볼 수 있습니다.

=를 이용한 패딩

입력 길이가 3의 배수가 아니면 마지막 그룹이 불완전해집니다. Base64는 비트를 0으로 채우고 = 문자를 덧붙여 출력 길이가 항상 4의 배수가 되도록 합니다.

  • 남는 바이트가 1개면 2문자 뒤에 ==가 붙습니다. 예: M → TQ==
  • 남는 바이트가 2개면 3문자 뒤에 =가 붙습니다. 예: Ma → TWE=
  • 남는 바이트가 없으면 패딩이 없습니다. 예: Man → TWFu

패딩 덕분에 디코더는 마지막 그룹에 실제 바이트가 몇 개 들어 있는지 알 수 있습니다. JWT에서 쓰는 Base64URL처럼 길이로 유추할 수 있어 패딩을 생략하는 형식도 있습니다.

33%의 크기 증가

3바이트가 4문자가 되므로 Base64 출력은 입력보다 약 33% 큽니다(원래 크기의 4/3을 4의 배수로 올림한 값). 300 KB 이미지는 약 400 KB의 텍스트가 됩니다. MIME 이메일처럼 76자마다 줄 바꿈을 넣으면 오버헤드가 조금 더 늘어납니다. 바이너리를 안전하게 전달하는 경로가 있다면 큰 파일을 Base64로 인코딩하지 말아야 하는 가장 큰 이유입니다.

Base64의 변형

  • 표준 Base64는 +와 /를 사용하고 =로 패딩합니다.
  • Base64URL은 +를 -로, /를 _로 바꿔 URL과 파일 이름에서 안전하게 쓸 수 있게 합니다. Base64URL vs Base64를 참고하세요.
  • MIME Base64는 이메일 규격에 따라 76자마다 줄 바꿈을 삽입합니다.

Base64가 아닌 것

Base64는 인코딩이지 암호화가 아닙니다. 누구나 즉시 되돌릴 수 있고 기밀성은 전혀 제공하지 않습니다. 비밀번호, API 키, 개인정보를 숨기는 데 절대 사용하지 마세요. 비밀 유지가 필요하다면 먼저 데이터를 암호화하고, 필요한 경우에만 전송을 위해 암호문을 Base64로 인코딩하세요.

Base64를 사용할 때

Base64는 텍스트만 허용하는 형식 안에 바이너리 데이터를 담아야 할 때 적합합니다. HTML이나 CSS에 작은 이미지를 포함하거나, API로 보내는 JSON 요청에 파일을 담거나, 설정 파일에 바이너리 키를 저장하거나, 이메일로 첨부 파일을 보낼 때가 그렇습니다. 큰 파일, 전송 경로가 이미 원시 바이트를 그대로 전달할 수 있는 데이터, 비밀로 유지해야 하는 정보에는 적합하지 않습니다.
