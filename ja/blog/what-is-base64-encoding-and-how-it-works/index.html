Base64エンコードとは？仕組みをわかりやすく解説

2026年11月読了時間約7分

Base64は、64種類の印字可能な文字だけでバイナリデータを表す方式です。電子メールの添付ファイル、JSONのペイロード、HTMLやCSSのdata URI、HTTPヘッダー、JWTトークン、設定ファイルなど、テキストしか扱えない経路でバイト列を運ぶ必要がある場面で広く使われています。これほど一般的であるにもかかわらず、Base64はしばしばブラックボックスとして扱われます。このガイドでは、何が行われているのかを一歩ずつ説明します。

Base64が必要な理由

多くのプロトコルは、任意のバイト列ではなくテキストを前提に設計されました。初期のメールシステム（SMTP）が保証していたのは、7ビットのASCIIテキストが変化せずに届くことだけです。JPEGやPDF、暗号化されたデータには、制御文字や改行、メッセージ終端の目印と取り違えられるバイト値が含まれ、転送経路が気づかないうちに書き換えたり拒否したりすることがあります。

Base64は、任意のバイト列を英字、数字、+、/だけで構成された文字列に変換することでこの問題を解決します。これらの文字は、ほぼあらゆるテキスト経路を変化せずに通過できます。受信側は処理を逆にたどり、元のバイト列を正確に復元します。

Base64のアルファベット

標準アルファベット（RFC 4648）の64文字は次のとおりです。

  • 値0〜25：A〜Z
  • 値26〜51：a〜z
  • 値52〜61：0〜9
  • 値62：+
  • 値63：/

65番目の文字=は、出力の末尾でパディングとしてのみ使われます。

アルゴリズムの仕組み

1バイトは8ビットですが、Base64の1文字が表せるのは6ビット（26 = 64通り）だけです。そのため、アルゴリズムは入力のビットを組み替えます。

  1. 入力を3バイト（24ビット）ずつ取り出す。
  2. その24ビットを6ビットずつ4つのグループに分ける。
  3. 各6ビットの値をアルファベットから探し、4文字の出力を得る。

入力3バイトが出力4文字になります。この比率が、後述するサイズ増加の理由です。

例：「Man」をエンコードする

テキストManはASCIIで3バイトです：M = 77、a = 97、n = 110。2進数で書くと次のようになります。

M = 01001101 a = 01100001 n = 01101110

24ビットをつなげ、6ビットずつ4グループに分けます。

010011 010110 000101 101110

これらのグループは数値の19、22、5、46にあたります。アルファベットで引くとT、W、F、uになります。つまり：

Man → TWFu

確認するには、Manをトップページのエンコーダーに貼り付けてください。

=によるパディング

入力の長さが3の倍数でない場合、最後のグループが不完全になります。Base64は、ビットを0で埋め、=を付け足して、出力の長さが常に4の倍数になるようにします。

  • 1バイト余る場合は、2文字に==が付きます。例：M → TQ==
  • 2バイト余る場合は、3文字に=が付きます。例：Ma → TWE=
  • 余りがない場合は、パディングは付きません。例：Man → TWFu

パディングにより、デコーダーは最後のグループに実際のバイトがいくつ含まれるかを知ることができます。JWTで使われるBase64URLのように、長さから推測できるためパディングを省く形式もあります。

33%のサイズ増加

3バイトが4文字になるため、Base64の出力は入力より約33%大きくなります（元のサイズの4/3を4の倍数に切り上げた値）。300 KBの画像は約400 KBのテキストになります。さらにMIMEメールのように76文字ごとに改行を入れると、オーバーヘッドはわずかに増えます。バイナリを安全に扱える経路があるなら、大きなファイルをBase64でエンコードしない主な理由はこれです。

Base64のバリエーション

  • 標準Base64は+と/を使い、=でパディングします。
  • Base64URLは+を-に、/を_に置き換え、URLやファイル名で安全に使えるようにしたものです。Base64URLとBase64の違いもご覧ください。
  • MIME Base64は、電子メールの要件に従って76文字ごとに改行を挿入します。

Base64ではないもの

Base64はエンコードであり、暗号化ではありません。誰でもすぐに元へ戻せるため、機密性はまったくありません。パスワード、APIキー、個人情報を隠す目的で使ってはいけません。秘匿が必要な場合は、先にデータを暗号化し、必要なら転送のために暗号文をBase64でエンコードしてください。

Base64を使う場面

Base64が適しているのは、テキストしか扱えない形式の中でバイナリデータを運ぶ必要があるときです。たとえば、HTMLやCSSに小さな画像を埋め込む、APIへのJSONリクエストにファイルを含める、設定ファイルにバイナリの鍵を保存する、メールで添付ファイルを送る、といった場面です。大きなファイル、転送経路がすでに生のバイト列を運べるデータ、秘密にしなければならないものには向きません。
