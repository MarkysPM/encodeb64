Was ist Base64-Kodierung und wie funktioniert sie?

November 20267 Min. Lesezeit

Base64 ist eine Methode, Binärdaten mit nur 64 druckbaren Zeichen darzustellen. Es wird überall eingesetzt, wo Bytes über einen Kanal übertragen werden müssen, der nur Text versteht: E-Mail-Anhänge, JSON-Nutzdaten, Data-URIs in HTML und CSS, HTTP-Header, JWT-Tokens und Konfigurationsdateien. Trotz seiner Verbreitung wird Base64 oft wie eine Blackbox behandelt. Dieser Leitfaden erklärt Schritt für Schritt, was genau passiert.

Warum es Base64 gibt

Viele Protokolle wurden für Text entworfen, nicht für beliebige Bytes. Frühe E-Mail-Systeme (SMTP) garantierten nur, dass 7-Bit-ASCII-Text unverändert ankommt. Ein JPEG, ein PDF oder ein verschlüsselter Block enthält Bytewerte, die mit Steuerzeichen, Zeilenenden oder Nachrichtenende-Markierungen verwechselt werden können, und der Transportweg kann sie stillschweigend verändern oder ablehnen.

Base64 löst das, indem es jede Bytefolge in eine Zeichenkette aus Buchstaben, Ziffern, + und / umwandelt. Diese Zeichen überstehen fast jeden Textkanal unverändert. Der Empfänger kehrt den Vorgang um und erhält exakt die ursprünglichen Bytes zurück.

Das Base64-Alphabet

Die 64 Zeichen des Standardalphabets (RFC 4648) sind:

  • Werte 0–25: A bis Z
  • Werte 26–51: a bis z
  • Werte 52–61: 0 bis 9
  • Wert 62: +
  • Wert 63: /

Ein 65. Zeichen, =, dient nur als Padding am Ende der Ausgabe.

So funktioniert der Algorithmus

Ein Byte hat 8 Bit, ein Base64-Zeichen kann aber nur 6 Bit darstellen (26 = 64 Werte). Der Algorithmus gruppiert die Eingabebits daher neu:

  1. Die Eingabe wird jeweils in Blöcken von drei Bytes (24 Bit) gelesen.
  2. Diese 24 Bit werden in vier Gruppen zu je 6 Bit aufgeteilt.
  3. Jeder 6-Bit-Wert wird im Alphabet nachgeschlagen, sodass vier Ausgabezeichen entstehen.

Drei Bytes Eingabe ergeben vier Zeichen Ausgabe. Dieses Verhältnis ist der Grund für den weiter unten beschriebenen Größenzuwachs.

Ein Beispiel: „Man“ kodieren

Der Text Man besteht in ASCII aus drei Bytes: M = 77, a = 97, n = 110. Binär:

M = 01001101 a = 01100001 n = 01101110

Fügen Sie die 24 Bit zusammen und teilen Sie sie in vier Gruppen zu je sechs Bit:

010011 010110 000101 101110

Diese Gruppen entsprechen den Zahlen 19, 22, 5 und 46. Im Alphabet nachgeschlagen ergibt das T, W, F und u. Also:

Man → TWFu

Sie können das prüfen, indem Sie Man in den Encoder auf der Startseite einfügen.

Padding mit =

Ist die Länge der Eingabe kein Vielfaches von drei, bleibt die letzte Gruppe unvollständig. Base64 füllt die Bits dann mit Nullen auf und hängt =-Zeichen an, damit die Länge der Ausgabe immer ein Vielfaches von vier ist:

  • Ein übriges Byte ergibt zwei Zeichen plus ==. Beispiel: M → TQ==
  • Zwei übrige Bytes ergeben drei Zeichen plus =. Beispiel: Ma → TWE=
  • Kein übriges Byte ergibt kein Padding. Beispiel: Man → TWFu

Das Padding verrät dem Decoder, wie viele echte Bytes die letzte Gruppe enthält. Manche Formate, etwa Base64URL in JWTs, lassen das Padding weg, weil sich die Länge ableiten lässt.

Der Größenzuwachs von 33 %

Weil aus je 3 Bytes 4 Zeichen werden, ist die Base64-Ausgabe etwa 33 % größer als die Eingabe (4/3 der Originalgröße, aufgerundet auf ein Vielfaches von vier). Ein Bild mit 300 KB wird zu rund 400 KB Text. Wird die Ausgabe zusätzlich in Zeilen umbrochen, wie bei MIME-E-Mails alle 76 Zeichen, wächst der Overhead etwas weiter. Das ist der Hauptgrund, große Dateien nicht in Base64 zu kodieren, wenn ein binärsicherer Kanal zur Verfügung steht.

Base64-Varianten

  • Standard-Base64 verwendet + und / mit =-Padding.
  • Base64URL ersetzt + durch - und / durch _, damit das Ergebnis in URLs und Dateinamen sicher ist. Siehe Base64URL vs Base64.
  • MIME-Base64 fügt alle 76 Zeichen einen Zeilenumbruch ein, wie es E-Mail verlangt.

Was Base64 nicht ist

Base64 ist eine Kodierung, keine Verschlüsselung. Jeder kann sie sofort umkehren, und sie bietet keinerlei Vertraulichkeit. Verwenden Sie sie niemals, um Passwörter, API-Schlüssel oder persönliche Daten zu verbergen. Wenn Sie Geheimhaltung brauchen, verschlüsseln Sie die Daten zuerst und kodieren den Chiffretext bei Bedarf anschließend für den Transport in Base64.

Wann Base64 sinnvoll ist

Base64 eignet sich, wenn Binärdaten in einem reinen Textformat transportiert werden müssen: ein kleines Bild in HTML oder CSS einbetten, eine Datei in eine JSON-Anfrage an eine API packen, einen binären Schlüssel in einer Konfigurationsdatei speichern oder Anhänge per E-Mail versenden. Ungeeignet ist es für große Dateien, für Daten, die Ihr Transportweg bereits als rohe Bytes befördern kann, und für alles, was geheim bleiben muss.
