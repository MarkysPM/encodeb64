JWT 令牌如何使用 Base64URL 编码

2026年8月阅读时间约 6 分钟

JSON Web Token（JWT）在现代 Web 开发中随处可见——用于身份验证、授权以及服务之间的信息交换。如果你仔细观察过一个 JWT 字符串，会发现它由三段以点分隔的部分组成，看起来像是随机的 Base64 文本。理解 JWT 的结构以及为什么使用 Base64URL，能帮助你排查身份验证问题，并更自信地处理令牌。

JWT 的结构

一个 JWT 看起来像这样：

eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6IkpvaG4gRG9lIiwiaWF0IjoxNTE2MjM5MDIyfQ.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c

由点分隔的三部分分别是：

  1. Header——描述令牌类型和签名算法
  2. Payload——包含令牌中编码的 claim（数据）
  3. Signature——用于验证令牌未被篡改

为什么使用 Base64URL 而不是标准 Base64？

JWT 通常在 HTTP 头（Authorization: Bearer ...）、URL 查询参数和 Cookie 中传输。标准 Base64 使用 + 和 /，在这些场景中会出问题——+ 在 URL 中会被解释为空格，/ 是路径分隔符。Base64URL 用 - 和 _ 替换它们，并去除 = 填充，使整个 JWT 无需百分号编码即可安全地放入任何 HTTP 上下文中。

解码 Header

上面示例 JWT 的第一部分——eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9——是经过 Base64URL 编码的 header。解码后得到：

{"alg":"HS256","typ":"JWT"}

这表明该令牌是使用 HMAC SHA-256 签名的 JWT。"alg" 字段至关重要——它告诉接收服务器在验证签名时应使用哪种算法。

解码 Payload

第二部分——eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6IkpvaG4gRG9lIiwiaWF0IjoxNTE2MjM5MDIyfQ——解码后得到：

{"sub":"1234567890","name":"John Doe","iat":1516239022}

这些就是令牌的 claim。标准 claim 包括：

  • sub（subject）——通常是用户 ID
  • iat（issued at）——令牌创建时的 Unix 时间戳
  • exp（expiration）——令牌过期时的 Unix 时间戳
  • iss（issuer）——创建该令牌的服务

签名无法解码（它不是 Base64URL 数据）

第三部分是签名——由 header 和 payload 结合密钥计算出的密码学哈希值。它用于验证令牌确实由可信方创建，且未被修改。你无法把签名解码成可读文本，因为它是二进制密码学数据，而不是 JSON。只有持有密钥的服务器才能验证它。

重要提示：解码不等于验证

一个常见的误解是：任何人都可以解码 JWT 的 payload 并读取其中的 claim。Base64URL 编码本身不提供任何安全性——它只是一种将 JSON 表示为 URL 安全字符串的方式。真正提供安全性的是签名验证。在信任 payload 中的任何 claim 之前，请务必在你的服务器上验证 JWT 的签名。

如何为调试解码 JWT

在开发过程中检查 JWT：

  1. 复制 JWT 字符串
  2. 将 header 或 payload 部分（第一个或第二个点之前的文本）粘贴到 decodeb64.com
  3. 解码后的 JSON 会显示其中的 claim

你也可以直接粘贴完整的 JWT——该工具会解码它能解析的第一部分。对于生产环境调试，建议使用专门的 JWT 检查工具，它同时还能显示签名相关信息。

常见的 JWT 编码错误

错误：解码 JWT 时出现“Invalid Base64 input”
原因：你使用的是不支持 - 和 _ 字符的标准 Base64 解码器。请使用支持 Base64URL 的解码器。

错误：payload 显示出意外字符或乱码
原因：JWT 的 claim 可能使用了非 UTF-8 编码，或字符串在传输过程中被损坏。请检查是否存在截断或字符替换问题。

现在就试着解码一个 JWT

将任意 JWT 的 payload 粘贴到 decodeb64.com——解码器会自动处理 Base64URL 输入，在解码前把 - 转换为 +、把 _ 转换为 /，无需手动替换字符。

JWT 的优雅之处在于其简洁性：三段以点分隔的 Base64URL 编码内容，并经过签名以防止篡改。理解其结构能让你更轻松地调试身份验证流程、在开发过程中检查令牌 claim，并与使用基于 JWT 的身份验证的第三方 API 进行集成。
