命令行中的 Base64：Linux、macOS 和 Windows

2026年11月阅读时间约 6 分钟

处理 Base64 并不需要网站或脚本。所有主流操作系统都自带可在终端中对其进行编码和解码的工具，适合检查令牌、为配置文件生成密钥，或转换小文件。本文涵盖 Linux、macOS 和 Windows，并指出会导致结果令人困惑的差异。

Linux：base64 命令

GNU 的 base64 命令属于 coreutils，几乎所有 Linux 发行版都已安装。

编码一个字符串：

echo -n 'Hello, World!' | base64 # SGVsbG8sIFdvcmxkIQ==

解码：

echo 'SGVsbG8sIFdvcmxkIQ==' | base64 --decode # Hello, World!

编码和解码文件：

base64 photo.png > photo.b64 base64 --decode photo.b64 > photo-copy.png

结尾换行的陷阱

这是最常见的错误。普通的 echo 会在输出末尾添加一个换行符，而这个换行符会成为被编码数据的一部分：

echo 'Hello' | base64 # SGVsbG8K (encodes "Hello\n") echo -n 'Hello' | base64 # SGVsbG8= (encodes "Hello")

如果密码、API 密钥或令牌在终端中编码后“不起作用”，多出来的换行符很可能就是罪魁祸首。请始终使用 echo -n，或使用 printf '%s' 'Hello'，后者在所有 shell 中表现一致。

输出的换行折行

GNU 的 base64 会在 76 个字符后折行。这对文件没有问题，但不适合粘贴进 JSON、环境变量或 HTTP 标头。用 -w 0 可以关闭折行：

base64 -w 0 photo.png

macOS

macOS 自带的是 BSD 版本的 base64，所支持的选项略有不同。通过管道进行基本编码的方式相同：

echo -n 'Hello, World!' | base64 echo 'SGVsbG8sIFdvcmxkIQ==' | base64 --decode

用 -i 指定输入文件，用 -o 指定输出文件：

base64 -i photo.png -o photo.b64

macOS 上没有 GNU 的 -w 0 选项，较旧的 macOS 版本使用 -D 而不是 -d 或 --decode。如果脚本需要在两个系统上都能运行，请判断平台，或使用下文介绍的 openssl。

openssl：可移植的选择

OpenSSL 在 Linux、macOS 和 Windows（通过 Git for Windows 或 WSL）上都可用，而且行为一致：

echo -n 'Hello, World!' | openssl base64 echo 'SGVsbG8sIFdvcmxkIQ==' | openssl base64 -d openssl base64 -in photo.png -out photo.b64

添加 -A 可让输出保持在一行，而不是折行。

Windows PowerShell

PowerShell 可以直接调用 .NET 的 Convert 类。编码文本：

[Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes('Hello, World!')) # SGVsbG8sIFdvcmxkIQ==

解码文本：

[Text.Encoding]::UTF8.GetString([Convert]::FromBase64String('SGVsbG8sIFdvcmxkIQ==')) # Hello, World!

把文件编码为 Base64 字符串：

[Convert]::ToBase64String([IO.File]::ReadAllBytes('photo.png'))

把 Base64 字符串解码写入文件：

[IO.File]::WriteAllBytes('photo-copy.png', [Convert]::FromBase64String($base64))

请注意，文本编码要显式指定（UTF8）。如果改用 Unicode，PowerShell 会使用 UTF-16，结果就会与 Linux 和 macOS 的不同。

Windows certutil

传统工具 certutil 可在任何 Windows 系统的命令提示符中使用：

certutil -encode photo.png photo.b64 certutil -decode photo.b64 photo-copy.png

请注意，certutil -encode 会在输出前后加上 -----BEGIN CERTIFICATE----- 的头尾行。如果只需要 Base64 文本，请删除这些行。

在终端中解码 Base64URL

JWT 和许多现代 API 使用 URL 安全字母表并省略填充，因此简单的 base64 --decode 可能会失败。请先转换字符并恢复填充：

value='eyJhbGciOiJIUzI1NiJ9' len=$(( ${#value} % 4 )) [ $len -eq 2 ] && value="$value==" [ $len -eq 3 ] && value="$value=" echo "$value" | tr '_-' '/+' | base64 --decode # {"alg":"HS256"}

想了解这些令牌为何看起来不同，请阅读JWT 令牌如何使用 Base64URL 编码。

快速对比

  • Linux：base64，用 -w 0 输出单行。
  • macOS：base64 配合 -i 和 -o；没有 -w 选项。
  • 跨平台：openssl base64。
  • Windows：PowerShell 的 [Convert] 或 certutil。

如果只是偶尔用一下，在线编码器和 decodeb64.com 可以在浏览器中完成同样的工作。想在程序中使用 Base64，请参阅 JavaScript 和 Python 指南。
