Base64 em Java, C#, Go e PHP: exemplos de código

Novembro de 20267 min de leitura

Toda linguagem popular traz suporte a Base64, mas os nomes, os padrões e o comportamento em caso de falha diferem de formas que causam bugs reais, principalmente em saída segura para URL, preenchimento e entrada inválida. Este guia traz exemplos compactos e prontos para copiar em Java, C#, Go e PHP, e aponta as diferenças que vale conhecer. Para JavaScript e Python, veja nossos guias de JavaScript e Python.

A string de teste usada nestes exemplos

Todos os exemplos codificam o texto Hello, World!, que deve produzir o mesmo resultado em qualquer linguagem:

SGVsbG8sIFdvcmxkIQ==

Se a sua saída for diferente, verifique a codificação de caracteres. Sempre converta o texto para bytes UTF-8 antes de codificar; caso contrário, os resultados diferem entre plataformas para texto não ASCII.

Java

Desde o Java 8, a classe java.util.Base64 é a ferramenta padrão. Evite o antigo sun.misc.BASE64Encoder e utilitários de terceiros em código novo.

import java.util.Base64; import java.nio.charset.StandardCharsets; String encoded = Base64.getEncoder() .encodeToString("Hello, World!".getBytes(StandardCharsets.UTF_8)); // SGVsbG8sIFdvcmxkIQ== byte[] decoded = Base64.getDecoder().decode(encoded); String text = new String(decoded, StandardCharsets.UTF_8);

O Java oferece três famílias de codificadores e decodificadores:

  • getEncoder() e getDecoder() para Base64 padrão.
  • getUrlEncoder() e getUrlDecoder() para o alfabeto seguro para URL.
  • getMimeEncoder() e getMimeDecoder() para MIME, que quebra linhas em 76 caracteres e ignora quebras de linha ao decodificar.

Para remover o preenchimento =, como faz o JWT, encadeie withoutPadding():

String token = Base64.getUrlEncoder().withoutPadding() .encodeToString("subjects?_d".getBytes(StandardCharsets.UTF_8)); // c3ViamVjdHM_X2Q

Entrada inválida lança IllegalArgumentException. Por exemplo, decodificar com o decodificador padrão uma string que contém um espaço falha com uma mensagem como Illegal base64 character 20 (o código hexadecimal do espaço). Se a sua entrada puder conter quebras de linha, use getMimeDecoder().

C# e .NET

A classe Convert cuida do Base64 padrão:

using System; using System.Text; string encoded = Convert.ToBase64String(Encoding.UTF8.GetBytes("Hello, World!")); // SGVsbG8sIFdvcmxkIQ== byte[] decoded = Convert.FromBase64String(encoded); string text = Encoding.UTF8.GetString(decoded);

Convert.FromBase64String lança FormatException com entrada inválida. Para evitar exceções em caminhos críticos, use o padrão sem exceções com Convert.TryFromBase64String e um buffer pré-alocado.

A classe clássica Convert não tem modo seguro para URL. As versões recentes do .NET adicionam uma classe Base64Url em System.Buffers.Text, e o ASP.NET Core oferece WebEncoders.Base64UrlEncode. Se nenhuma estiver disponível, converta manualmente:

string url = Convert.ToBase64String(bytes) .TrimEnd('=') .Replace('+', '-') .Replace('/', '_');

Mais uma armadilha: Encoding.Unicode no .NET é UTF-16, não UTF-8. Usá-lo produz um Base64 diferente do da maioria das linguagens.

Go

O pacote encoding/base64 expõe codificações prontas como variáveis, de modo que a escolha do alfabeto e do preenchimento é explícita:

import "encoding/base64" encoded := base64.StdEncoding.EncodeToString([]byte("Hello, World!")) // SGVsbG8sIFdvcmxkIQ== decoded, err := base64.StdEncoding.DecodeString(encoded) if err != nil { // invalid input } text := string(decoded)

As quatro codificações padrão são:

  • StdEncoding: alfabeto padrão, com preenchimento.
  • URLEncoding: alfabeto seguro para URL, com preenchimento.
  • RawStdEncoding: alfabeto padrão, sem preenchimento.
  • RawURLEncoding: alfabeto seguro para URL, sem preenchimento. É a que as bibliotecas JWT usam.

O Go é rigoroso. Decodificar com StdEncoding uma string cujo preenchimento foi removido falha com um erro como illegal base64 data at input byte N, então você precisa escolher a codificação que corresponda exatamente aos seus dados.

PHP

O PHP tem duas funções nativas:

$encoded = base64_encode('Hello, World!'); // SGVsbG8sIFdvcmxkIQ== $decoded = base64_decode($encoded, true); if ($decoded === false) { // invalid input }

Sempre passe true como segundo argumento de base64_decode. Sem ele, o PHP ignora em silêncio os caracteres fora do alfabeto, então uma entrada malformada pode gerar lixo em vez de um erro. No modo estrito a função retorna false com entrada inválida.

O PHP não tem funções nativas seguras para URL, então use strtr:

function base64url_encode(string $data): string { return rtrim(strtr(base64_encode($data), '+/', '-_'), '='); } function base64url_decode(string $data): string|false { return base64_decode(strtr($data, '-_', '+/')); }

Diferenças de comportamento num relance

  • Preenchimento ao decodificar: o decodificador URL do Java aceita preenchimento ausente, o Go exige que você escolha uma codificação Raw e o FromBase64String do .NET espera o preenchimento correto.
  • Espaços em branco: o decodificador MIME do Java ignora quebras de linha; os decodificadores padrão de Java, Go e .NET rejeitam espaços na maioria dos casos; o PHP os descarta no modo não estrito.
  • Erros: o Java lança IllegalArgumentException, o .NET lança FormatException, o Go retorna um error e o PHP retorna false no modo estrito.

Para ajuda com as mensagens acima, leia Erros comuns de Base64 e como corrigi-los.
