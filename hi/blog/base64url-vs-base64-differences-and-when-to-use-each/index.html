Base64URL बनाम Base64: अंतर और कब किसका उपयोग करें

अगस्त 20264 मिनट पढ़ने का समय

अगर आपने JWT टोकन, OAuth 2.0 या URL पैरामीटर के साथ काम किया है, तो आपको शायद Base64URL का सामना करना पड़ा होगा — यह स्टैंडर्ड Base64 का एक वेरिएंट है जो लगभग एक जैसा दिखता है, लेकिन कुछ संदर्भों में अलग तरह से व्यवहार करता है। इस अंतर को समझने से आप रहस्यमय एन्कोडिंग एरर को डीबग करने में लगने वाले घंटों को बचा सकते हैं।

स्टैंडर्ड Base64 क्या है?

RFC 4648 §4 में परिभाषित स्टैंडर्ड Base64, बाइनरी डेटा को 64 वर्णों का उपयोग करके एन्कोड करता है: A–Z, a–z, 0–9, प्लस (+), और स्लैश (/)। लंबाई को 4 का गुणज बनाने के लिए आउटपुट को इक्वल साइन (=) से पैड किया जाता है। उदाहरण के लिए, "Man" को एन्कोड करने पर "TWFu" मिलता है।

समस्या तब आती है जब आप किसी URL में स्टैंडर्ड Base64 स्ट्रिंग का उपयोग करने की कोशिश करते हैं। URL क्वेरी स्ट्रिंग में + को स्पेस के रूप में समझा जाता है, और / एक पाथ सेपरेटर है। "abc+def/ghi=" जैसी Base64 स्ट्रिंग को URL में रखने पर वेब सर्वर और ब्राउज़र इसे गलत तरीके से समझेंगे।

Base64URL क्या है?

RFC 4648 §5 में परिभाषित Base64URL, दो प्रतिस्थापन करके इसे हल करता है:

  • + को - (हाइफ़न) से बदला जाता है
  • / को _ (अंडरस्कोर) से बदला जाता है
  • = पैडिंग को पूरी तरह हटा दिया जाता है

ये सभी वर्ण बिना पर्सेंट-एनकोडिंग के URL और फ़ाइल नामों में सुरक्षित होते हैं। यही "Man" उदाहरण दोनों वेरिएंट में "TWFu" के रूप में एन्कोड होता है (इस मामले में कोई विशेष वर्ण नहीं है), लेकिन स्टैंडर्ड Base64 में "i+Uo/A==" जैसी स्ट्रिंग, Base64URL में "i-Uo_A" बन जाती है।

JWT टोकन Base64URL का उपयोग करते हैं

JSON Web Token (JWT) वह जगह है जहाँ डेवलपर्स को सबसे अधिक Base64URL का सामना करना पड़ता है। एक JWT तीन डॉट-सेपरेटेड भागों से बना होता है: header.payload.signature। हेडर और पेलोड दोनों Base64URL में एन्कोड होते हैं — स्टैंडर्ड Base64 में नहीं। यही कारण है कि JWT स्ट्रिंग में हाइफ़न और अंडरस्कोर होते हैं, लेकिन कभी प्लस साइन या स्लैश नहीं होते।

यदि आप वर्णों को पहले बदले बिना किसी JWT को स्टैंडर्ड Base64 डिकोडर में पेस्ट करते हैं, तो आपको डिकोडिंग एरर या बेतरतीब आउटपुट मिलेगा। JWT के लिए हमेशा Base64URL-संगत डिकोडर का उपयोग करें।

दोनों के बीच रूपांतरण

स्टैंडर्ड Base64 स्ट्रिंग को Base64URL में बदलने के लिए:

  1. सभी + को - से बदलें
  2. सभी / को _ से बदलें
  3. सभी = पैडिंग वर्ण हटा दें

Base64URL को वापस स्टैंडर्ड Base64 में बदलने के लिए:

  1. सभी - को + से बदलें
  2. सभी _ को / से बदलें
  3. स्ट्रिंग की लंबाई 4 का गुणज होने तक = पैडिंग जोड़ें

कब किसका उपयोग करें

स्टैंडर्ड Base64 का उपयोग करें जब:

  • ईमेल अटैचमेंट एन्कोड करें (MIME, RFC 2045)
  • HTML और CSS में इमेज को Data URI के रूप में एम्बेड करें
  • JSON या XML पेलोड में बाइनरी डेटा स्टोर करें जहाँ वैल्यू कोट्स में हो
  • ऐसे सिस्टम के साथ काम करें जिन्हें विशेष रूप से स्टैंडर्ड Base64 की आवश्यकता होती है

Base64URL का उपयोग करें जब:

  • JWT टोकन जनरेट या पार्स करें
  • OAuth 2.0 PKCE चैलेंज के लिए URL-सुरक्षित टोकन बनाएं
  • URL क्वेरी पैरामीटर या पाथ सेगमेंट के लिए डेटा एन्कोड करें
  • बाइनरी डेटा से फ़ाइल नाम बनाएं (अधिकांश सिस्टम में फ़ाइल नामों में / नहीं हो सकता)
  • वेब क्रिप्टोग्राफ़ी API के साथ काम करें, जो सामान्यतः Base64URL आउटपुट देते हैं
