Base64URL vs Base64: Differences and When to Use Each

August 20264 min read

If you have worked with JWT tokens, OAuth 2.0, or URL parameters, you have probably encountered Base64URL — a variant of standard Base64 that looks almost identical but behaves differently in certain contexts. Understanding the distinction can save you hours of debugging cryptic encoding errors.

What Is Standard Base64?

Standard Base64, defined in RFC 4648 §4, encodes binary data using 64 characters: A–Z, a–z, 0–9, plus (+), and slash (/). Output is padded with equals signs (=) to make the length a multiple of 4. For example, encoding "Man" gives "TWFu".

The problem arises when you try to use a standard Base64 string in a URL. The + character is interpreted as a space in URL query strings, and / is a path separator. A Base64 string like "abc+def/ghi=" placed in a URL will be misinterpreted by web servers and browsers.

What Is Base64URL?

Base64URL, defined in RFC 4648 §5, solves this by making two substitutions:

  • + is replaced by - (hyphen)
  • / is replaced by _ (underscore)
  • = padding is omitted entirely

These characters are all safe in URLs and filenames without percent-encoding. The same "Man" example encodes to "TWFu" in both variants (no special characters in this case), but a string like "i+Uo/A==" in standard Base64 becomes "i-Uo_A" in Base64URL.

JWT Tokens Use Base64URL

JSON Web Tokens (JWT) are the most common place developers encounter Base64URL. A JWT consists of three dot-separated parts: header.payload.signature. Both the header and payload are Base64URL encoded — not standard Base64. This is why JWT strings contain hyphens and underscores but never plus signs or slashes.

If you paste a JWT into a standard Base64 decoder without converting the characters first, you will get a decoding error or garbage output. Always use a Base64URL-aware decoder for JWTs.

Converting Between the Two

To convert a standard Base64 string to Base64URL:

  1. Replace all + with -
  2. Replace all / with _
  3. Remove all = padding characters

To convert Base64URL back to standard Base64:

  1. Replace all - with +
  2. Replace all _ with /
  3. Add = padding until the string length is a multiple of 4

When to Use Each

Use standard Base64 when:

  • Encoding email attachments (MIME, RFC 2045)
  • Embedding images as Data URIs in HTML and CSS
  • Storing binary data in JSON or XML payloads where the value is quoted
  • Working with systems that specifically require standard Base64

Use Base64URL when:

  • Generating or parsing JWT tokens
  • Creating URL-safe tokens for OAuth 2.0 PKCE challenges
  • Encoding data for URL query parameters or path segments
  • Creating filenames from binary data (filenames cannot contain / on most systems)
  • Working with web cryptography APIs, which typically output Base64URL

The difference between Base64 and Base64URL is small but important. When in doubt, check the specification of the system you are integrating with — JWT always means Base64URL, while MIME always means standard Base64 with line breaks. Using the wrong variant is one of the most common causes of encoding bugs in web applications.
