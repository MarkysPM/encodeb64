Base64 en Java, C#, Go y PHP: ejemplos de código

Noviembre de 20267 min de lectura

Todos los lenguajes principales incluyen soporte de Base64, pero los nombres, los valores por defecto y el comportamiento ante fallos difieren de maneras que causan errores reales, sobre todo con la salida segura para URL, el relleno y la entrada inválida. Esta guía te da ejemplos compactos y listos para copiar en Java, C#, Go y PHP, y señala las diferencias que conviene conocer. Para JavaScript y Python, consulta nuestras guías de JavaScript y Python.

La cadena de prueba de estos ejemplos

Todos los ejemplos codifican el texto Hello, World!, que debería dar el mismo resultado en todos los lenguajes:

SGVsbG8sIFdvcmxkIQ==

Si tu salida es distinta, revisa la codificación de caracteres. Convierte siempre el texto a bytes UTF-8 antes de codificar; si no, los resultados difieren entre plataformas con texto no ASCII.

Java

Desde Java 8, la clase java.util.Base64 es la herramienta estándar. Evita el antiguo sun.misc.BASE64Encoder y las utilidades de terceros en código nuevo.

import java.util.Base64; import java.nio.charset.StandardCharsets; String encoded = Base64.getEncoder() .encodeToString("Hello, World!".getBytes(StandardCharsets.UTF_8)); // SGVsbG8sIFdvcmxkIQ== byte[] decoded = Base64.getDecoder().decode(encoded); String text = new String(decoded, StandardCharsets.UTF_8);

Java ofrece tres familias de codificadores y decodificadores:

  • getEncoder() y getDecoder() para Base64 estándar.
  • getUrlEncoder() y getUrlDecoder() para el alfabeto seguro para URL.
  • getMimeEncoder() y getMimeDecoder() para MIME, que parte las líneas a los 76 caracteres e ignora los saltos de línea al decodificar.

Para quitar el relleno =, como hace JWT, encadena withoutPadding():

String token = Base64.getUrlEncoder().withoutPadding() .encodeToString("subjects?_d".getBytes(StandardCharsets.UTF_8)); // c3ViamVjdHM_X2Q

La entrada inválida lanza IllegalArgumentException. Por ejemplo, decodificar con el decodificador estándar una cadena que contiene un espacio falla con un mensaje como Illegal base64 character 20 (el código hexadecimal del espacio). Si tu entrada puede contener saltos de línea, usa getMimeDecoder().

C# y .NET

La clase Convert gestiona el Base64 estándar:

using System; using System.Text; string encoded = Convert.ToBase64String(Encoding.UTF8.GetBytes("Hello, World!")); // SGVsbG8sIFdvcmxkIQ== byte[] decoded = Convert.FromBase64String(encoded); string text = Encoding.UTF8.GetString(decoded);

Convert.FromBase64String lanza FormatException con entrada inválida. Para evitar excepciones en rutas críticas, usa el patrón sin excepciones con Convert.TryFromBase64String y un búfer preasignado.

La clase clásica Convert no tiene modo seguro para URL. Las versiones recientes de .NET añaden una clase Base64Url en System.Buffers.Text, y ASP.NET Core ofrece WebEncoders.Base64UrlEncode. Si no tienes ninguna, convierte a mano:

string url = Convert.ToBase64String(bytes) .TrimEnd('=') .Replace('+', '-') .Replace('/', '_');

Otra trampa: Encoding.Unicode en .NET es UTF-16, no UTF-8. Usarlo produce un Base64 distinto del de la mayoría de lenguajes.

Go

El paquete encoding/base64 expone codificaciones ya hechas como variables, de modo que la elección de alfabeto y relleno es explícita:

import "encoding/base64" encoded := base64.StdEncoding.EncodeToString([]byte("Hello, World!")) // SGVsbG8sIFdvcmxkIQ== decoded, err := base64.StdEncoding.DecodeString(encoded) if err != nil { // invalid input } text := string(decoded)

Las cuatro codificaciones estándar son:

  • StdEncoding: alfabeto estándar, con relleno.
  • URLEncoding: alfabeto seguro para URL, con relleno.
  • RawStdEncoding: alfabeto estándar, sin relleno.
  • RawURLEncoding: alfabeto seguro para URL, sin relleno. Es la que usan las bibliotecas JWT.

Go es estricto. Decodificar con StdEncoding una cadena a la que se quitó el relleno falla con un error como illegal base64 data at input byte N, así que debes elegir la codificación que coincida exactamente con tus datos.

PHP

PHP tiene dos funciones integradas:

$encoded = base64_encode('Hello, World!'); // SGVsbG8sIFdvcmxkIQ== $decoded = base64_decode($encoded, true); if ($decoded === false) { // invalid input }

Pasa siempre true como segundo argumento de base64_decode. Sin él, PHP ignora en silencio los caracteres fuera del alfabeto, por lo que una entrada mal formada puede producir basura en lugar de un error. En modo estricto la función devuelve false con entrada inválida.

PHP no tiene funciones integradas seguras para URL, así que usa strtr:

function base64url_encode(string $data): string { return rtrim(strtr(base64_encode($data), '+/', '-_'), '='); } function base64url_decode(string $data): string|false { return base64_decode(strtr($data, '-_', '+/')); }

Diferencias de comportamiento de un vistazo

  • Relleno al decodificar: el decodificador URL de Java acepta relleno ausente, Go exige que elijas una codificación Raw y el FromBase64String de .NET espera el relleno correcto.
  • Espacios en blanco: el decodificador MIME de Java ignora los saltos de línea; los decodificadores estándar de Java, Go y .NET rechazan los espacios en la mayoría de casos; PHP los descarta en modo no estricto.
  • Errores: Java lanza IllegalArgumentException, .NET lanza FormatException, Go devuelve un error y PHP devuelve false en modo estricto.

Para ayuda con los mensajes anteriores, lee Errores comunes de Base64 y cómo solucionarlos.
